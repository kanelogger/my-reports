# 周报编辑标准

用于生成、撰写、编纂、重编周报。仅整理、预览或发布已确认稿时，不把本标准解释为重新改稿的授权。

## 先审视完整，再决定成刊

“本周大事不能漏”要求编辑认真审视重大候选，不要求每个候选都独立占一条正文。工作分两层：

- **素材层**：按指定周逐日看候选、来源、事件最新状态，记录展开／合并／简述／留档的理由。已有原始文件和 `review.md` 足以追溯时，不强制增加清单、哈希、JSON 或一套研究文件。
- **成刊层**：选择能代表本周变化的事件，决定篇幅、顺序和论点。完整清单留作编辑依据，不把盘点结果原样交给读者。

先看全周，避免漏掉头部公司或领军人物的重大变动；再按本期材料重定主线，避免为纠正遗漏而退回逐日流水账。

## 重要性如何判断

围绕读者需要重新判断的事情选择素材：

| 观察角度 | 值得展开的变化 | 适合降级处理的材料 |
| --- | --- | --- |
| 产品与工作流 | 用户能完成新的工作，接口、编排、权限或交付方式改变 | 功能菜单、小界面修改、重复演示和个人体感 |
| 技术与生产 | 标志性能力突破进入可用工具、执行环境或生产链路 | 单独版本号、参数、厂商跑分和例行更新 |
| 人物与产业 | 关键人物决策、去留或长期贡献，改变信任、合作或发展路径 | 私生活猎奇、没有产业含义的名人言论 |
| 商业条件 | 公开市场进程、结构性资本或供应链变化，影响服务能否持续 | 普通融资金额、投资者名单和未经确认的财务推测 |
| 政策与责任 | 重要国家／政府或平台的关键动作，直接改变市场准入、数据边界、采购或责任 | 一般政治动态、地区新闻、尚未改变产品条件的程序进展 |

偏产品与技术，不等于只写 Agent，也不等于排除硬科技或重要人物。政府只看重要少数及真正改变本期判断的动作，不机械设国家白名单、也不凑每个国家的代表。谁值得写、谁应占更多篇幅，由影响与证据决定。

“时势造英雄，但是英雄也能造时势”意味着同时观察结构条件与人的选择：算力、资本、市场会塑造机会；领军者、创造者和维护者也可能改变技术路线、工具与行业关系。用事件说明影响，不把这句话贴成口号，更不把公司宣传或个人崇拜当判断。

## 建立主次层次

- **主篇**：一个有分量的变化，交代事实，解释对哪类产品／用户／技术选择产生影响，给出编辑判断及依据。篇幅向最有解释力的内容倾斜。
- **合读**：多个进展确实解释同一个问题，合在一起支持一个论点。分清各自发生的层次与边界；消费入口、开发者 API、工作台编排和基础模型可以共同讨论，但不是同一个产品。
- **短便签**：保留对读者有即时价值的期限、升级、迁移或兼容提醒。只给必要动作和条件，不复述发行说明。
- **留档**：旧闻、普通更新、弱证据、重复内容或与本期主矛盾联系较弱的候选。主要取舍写进私人审阅记录，不用正文为每条未选消息辩解。

在常规六栏内按影响分配篇幅。「好文章」保留作者怎样论证、举了什么例子；「工具与项目」交代读者可以拿它做什么及使用条件。不同作者的独立分享各自展开，次要进展可在共同问题下合读。留档内容保存在私人材料里。

## 让判断有分量

一篇主稿应让读者理解：

1. 这周具体发生了什么动作，状态到哪一步。
2. 它改变了谁的工作、成本、权限、可用市场或责任。
3. 为什么编者把它放在这里，结论依据是什么，哪一处仍需验证。

事实与评论可分成相邻段落。用“我更看重”“在我看来”等自然表达标明归纳，也可直接提出有依据的观点；不必每篇机械加“事实／点评”标签。判断应落到具体影响，少用“非常重要”“全面加速”“值得持续关注”代替分析。

例如，多模型发布可以围绕“同一任务里怎样分工”组织，而不依次朗读厂商菜单；平台把搜索、文件或支付接进产品后，可以讨论业务流程和用户确认的价值。例子只是判断方式，下一期不必沿用同一叙事，也不保证同一家公司继续占主篇。

## 保留决定结论的事实边界

- 分清事件日、公告日、生效日、首发日和日报收录日。同一事件先有传闻、后有官方动作时合并进展；旧文再次被讨论，不冒作本周首发。
- 区分正式、测试、预览、私测、后续计划及已经完成；保留影响使用的地区、套餐、期限和入口条件。必要时把截止时间换成北京时间，来源日期保持清楚。
- 模型、工具、自托管执行和本地模型权重是不同能力；官方演示、特定测试与普遍性能也有不同证据强度。
- 人物去留、融资、政策、安全与严重指控优先依据原始公告或文件。媒体报道保留归属；起诉请求、独立调查和个人说法不升级为最终结论。看不到关键原文时记录不确定性，不补造确认。
- 补充资料围绕已有素材的关键日期、状态、范围和数字进行。不要为了完整性无限找新闻，也不要为消除所有不确定性阻止一份已有清楚归属的稿件预览。
- 选图时先问读者看完能明白哪一点。界面操作选能看见关键控件的真实画面，数据并列保留单位、分母和时间范围，研究进展区分已通过与待验证。署名、演示性质和编辑绘图身份随图保留。

## 成稿与审阅记录分开

正文是给读者看的，每个条目应有清晰的标题、足够展开的正文、与内容对应的配图及来源。日期和数字服务于理解，不要求每段都以日期起头。参数、价格、融资额与基准只在影响判断时保留。

“应保留”“适合写成”“待主代理处理”、候选清单、来源访问失败的详细过程、每条取舍与内部校验都放私人记录。引用资料有不确定性时，正文用必要的归属与限定说明；不要把整份工作日志搬进刊物。

`review.md` 最少能回答：本期素材范围与缺口、选了哪些主线、重要候选怎样处理、哪些事实有边界，以及当前预览／确认／发布状态。原始资料和旧稿备份保留，不要求每次都新建多个清单文件。

## 最后一遍编辑复核

读各栏标题与开头，检查它们是否让人记住少数有分量的变化；检查段落是否只是换了格式的发布目录；检查主要观点是否来自证据而非为了口号硬拼。若正文越来越长，回到重要性与读者影响重新取舍，不只做机械压缩。

完整性审计与专业编辑可以分工：子代理负责某类素材的补充、图像或反向复核，主编辑负责论点、叙事和版面层级。复核应找事实偏移、重要遗漏与论证问题，不把“每条都在正文出现”当作通过条件。
