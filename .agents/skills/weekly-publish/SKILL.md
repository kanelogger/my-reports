# 周报编纂与发布

这是项目内的周报编排入口，复用四个功能 Skill，不改写它们的职责。先读仓库 `AGENTS.md`、`README.md`「四个功能 Skill」「日报与周报」；进入编纂阶段时再读 [编辑标准](references/editorial-standard.md)。

核心原则：**先看全周，再判断主次；主要变化展开，次要进展整合。**

> 时势造英雄，但是英雄也能造时势。抓住主要矛盾，次要矛盾就整合带过。

## 先判断本次要求的阶段

| 用户请求 | 执行范围 |
| --- | --- |
| 生成、撰写、编纂或重编周报 | 默认交付常规六栏图文稿，包含封面、全期信息图和条目配图。按本期明确要求调整，保留原始资料与旧稿备份。 |
| 只整理、只分类、保留原文、只排版 | 按 [report-organize](../report-organize/SKILL.md) 的保留正文规则执行。 |
| 已有完整稿，只要求预览 | 直接用 [report-preview](../report-preview/SKILL.md)，不重新编纂。 |
| 最新预览已看过并确认，要求发布 | 直接用 [report-publish](../report-publish/SKILL.md)，不重新选题或重复索要已有确认。 |

自动选中或仅加载本技能不扩大授权。仅要求成稿或预览时完成到该阶段；仅创建、修改技能也不代表授权发布本期周报。

## 1. 确认期次与素材

- 周报期号用所属周周日，显示区间为北京时间周一至周日。检查工作区、当前分支、远端和上游，再确认该周日报、素材与现有草稿。
- **先判断资料是否过时，再声称本周缺稿。** 上游可能已有日报；在任务范围内获取并安全快进同步，保留用户本地修改。不能快进时可读取远端版本或另存临时素材，说明缺口；不自行强推、重置或隐藏用户改动。不静默用上一周替代本周。
- 首次导入按 [report-import](../report-import/SKILL.md) 初始化；已有人工稿先备份，再按当前授权修订。正文始终落在 `.local/weeklies/YYYY-MM-DD/draft.md`，原始资料和整理说明保留在本期私人目录。
- 以用户提供的资料为起点。查找配图限于已入选的新闻、文章和项目。补信息或核对指定原文依本次授权。来源全面核对不是发布前另加的一道审批。

## 2. 盘点、取舍与成稿

1. 逐日审视本周重要候选，兼顾模型与产品、关键人物和公司、资本与基础设施、安全及标志性科技进展。**不要先定一个偏爱的专题，再把重大事件排除。** 同一事件的传闻、正式公告和后续合并，以最新可确认状态为准。
2. **动笔前对照上一期正式周报**（`weeklies/` 中早于本期且日期最近的期次），看读者实际见到的目录、文章篇幅、封面和图文位置。常规刊使用六个二级标题，名称和顺序为 **本周焦点 → 模型与产品 → 行业大事记 → 科技与开源 → 好文章 → 工具与项目**。无上期可参考时也按此骨架编排。本期主题用作栏内三级标题；用户明确要求特刊、指定栏目或纯文字版时以本期要求为准。
3. 在已有 `review.md` 先排本期目录，给每条入选内容记下栏目、展开或合读的理由、拟配截图或图解。独立新闻、文章或工具各用一个三级标题。两场各有论点和材料的分享分别成篇，保留具体例子、关键决定与适用条件。各栏按本周素材分配篇幅；若某栏确无可靠素材，说明缺口。
4. 主编辑统一论点、篇幅与顺序。偏产品与技术，说明工作流、能力、成本、权限、可靠性或交付方式的变化；也审视关键人物的决策和长期影响。政府新闻只选重要少数国家／政府的关键动作，不凑国别，不平均分配厂商席位。
5. 事实与判断相邻但可区分。写清“发生了什么、改变了什么、我为何重视”；判断具体到产品、用户或技术选择，保留推断的证据边界。日期、预览／正式、地区、套餐、期限和自测条件只保留影响理解与使用的部分。
6. 栏内选题、篇数和压缩程度由编辑判断。次要消息按共同问题合并，避免把删下的清单搬到另一栏，也避免在一段里塞回全部名字。成稿面向读者，不保留“应写成”“待主代理处理”等采编指令。

可将资料补充、配图和终审交给子代理并行处理，限定各自素材范围与文件归属；子代理提出证据和建议，主编辑负责最终取舍。不要把“每类交一份完整清单”当作成刊结构。

## 3. 配图、预览与修订

- **封面、全期信息图、条目配图分别安排。** 卷首封面放在刊名与首栏之间，让读者看清期次和焦点。全期信息图提炼几项跨栏的重要事实、关系或数字，置于导读或焦点之后。每个已刊三级条目都要就近配能解释它的图。合读里有不同产品、事件或数据口径时，各自配图，或用标明对应关系的对照图。封面和全期图解不计入条目覆盖。
- 优先用对应版本的真实截图、官方演示截帧、资料照片或原始图表。缺合适实图就依据正文生成示意插画或绘制信息图。流程、对比和时间线优先用 **4:3 信息图**，例如 1200 × 900 像素。实图按内容取景，保留关键界面和标注。图注写清对象及来源，分别注明官方演示、资料照、编辑图解或 AI 示意；不伪造界面、事件现场、引文或数据。逐图出处和必要的署名、授权记入本期 `image-sources.md` 或 `review.md`。
- 图片放在本期 `images/`，以 `![可读图注](images/文件名)` 紧邻对应段落。支持 PNG、JPEG、GIF、WebP，单图最多 10 MB。沿用 `DESIGN.md` 第 10 节及 `lib/publication*` 正式模板。
- **常规稿在首次交预览前检查，修订后复查。** 在仓库根目录运行以下命令，替换为本期实际日期和图档路径。检查器只读草稿，按栏目和三级标题定位缺图项。先修好报告的栏目或缺图问题，再预览。相同图跨条出现时，由编辑核实它是否分别解释所配内容。用户指定的特刊、纯文字稿按本期约定验收。

```bash
node .agents/skills/weekly-publish/scripts/check-draft.js .local/weeklies/YYYY-MM-DD/draft.md images/cover.jpg images/week-in-figures.png &&
npm run weekly:preview -- YYYY-MM-DD
```

- 按 [report-preview](../report-preview/SKILL.md) 实看桌面和手机宽度。以渲染出的六栏目录及条目为准，检查全部图片成功加载、图注贴近正确段落、图文无裁切；在约 350 像素正文宽度下仍应认得主体、关键数字与单位。对照成稿判断每则消息是否配对，补好再交付。在 `review.md` 记下“已配图条目数 / 刊载条目数”、封面和全期图解的检查结果。总图数不能代替逐条点验。只生成文件可用 `--no-serve`。
- 改草稿、图片或模板后重跑预览，重启旧预览服务，核对正在提供的页面确为最新文件。不要只改磁盘文件却继续让用户看旧服务捕获的 HTML。
- 交付本期预览和主要取舍，服务供用户审阅时保持运行。**用户查看并确认最新预览后**才进入周报发布；自动化检查和预览哈希都不能代替人的确认。

## 4. 按授权定稿与发布

进入本阶段时加载 [report-publish](../report-publish/SKILL.md)，沿用其 Git、替换和部署边界，不另造发布流程。

```bash
npm run weekly:finalize -- YYYY-MM-DD
npm run build
```

- 正式文件是 `weeklies/YYYY-MM-DD.html`，须与用户最后确认的预览完全一致。沿用脚本对正文、HTML、图片和模板的校验，不手改校验记录绕过检查。替换既有同一期需有相应授权，再用 `--replace`。
- 确认三个生成索引、本期入口和历史资源正常，私人素材及技能未进入 `dist/`。不手改索引，不提交 `dist/`。
- 提交、PR、推送按本次授权和当前分支执行，只包含本次交付路径，保留无关修改。`main`／`master` 推送会触发 Pages；不要因技能名称含“发布”就自动推送。
- 已授权上线时继续核对对应提交的 Actions 和线上本期／归档入口。失败或无法确认时停在真实状态，不把提交、PR 或推送说成已经上线。

## 交付

简明报告期次、成稿／预览或正式入口、核心编辑取舍和检查结果。涉及发布时再附提交、分支／PR、部署与线上链接，明确实际完成阶段。内容、图片或模板变动使旧确认失效；没有变动且已有明确确认时继续执行，不重复询问。
