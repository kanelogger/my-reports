# 周报编纂与发布

这是项目内的周报编排入口，复用四个功能 Skill，不改写它们的职责。先读仓库 `AGENTS.md`、`README.md`「四个功能 Skill」「日报与周报」；进入编纂阶段时再读 [编辑标准](references/editorial-standard.md)。

核心原则：**先看全周，再判断主次；主要变化展开，次要进展整合。**

> 时势造英雄，但是英雄也能造时势。抓住主要矛盾，次要矛盾就整合带过。

## 先判断本次要求的阶段

| 用户请求 | 执行范围 |
| --- | --- |
| 生成、撰写、编纂或重编周报 | 允许对指定周报选题、摘要、合并、改写和补充编辑判断；保留原始资料与旧稿备份。 |
| 只整理、只分类、保留原文、只排版 | 按 [report-organize](../report-organize/SKILL.md) 的保留正文规则执行。 |
| 已有完整稿，只要求预览 | 直接用 [report-preview](../report-preview/SKILL.md)，不重新编纂。 |
| 最新预览已看过并确认，要求发布 | 直接用 [report-publish](../report-publish/SKILL.md)，不重新选题或重复索要已有确认。 |

自动选中或仅加载本技能不扩大授权。仅要求成稿或预览时完成到该阶段；仅创建、修改技能也不代表授权发布本期周报。

## 1. 确认期次与素材

- 周报期号用所属周周日，显示区间为北京时间周一至周日。检查工作区、当前分支、远端和上游，再确认该周日报、素材与现有草稿。
- **先判断资料是否过时，再声称本周缺稿。** 上游可能已有日报；在任务范围内获取并安全快进同步，保留用户本地修改。不能快进时可读取远端版本或另存临时素材，说明缺口；不自行强推、重置或隐藏用户改动。不静默用上一周替代本周。
- 首次导入按 [report-import](../report-import/SKILL.md) 初始化；已有人工稿先备份，再按当前授权修订。正文始终落在 `.local/weeklies/YYYY-MM-DD/draft.md`，原始资料和整理说明保留在本期私人目录。
- 以用户提供的资料为起点。补信息、核对指定原文与配图依本次授权；检索围绕已有候选的具体问题，不扩成全网采集。来源全面核对不是发布前另加的一道审批。

## 2. 盘点、取舍与成稿

1. 逐日审视本周重要候选，兼顾模型与产品、关键人物和公司、资本与基础设施、安全及标志性科技进展。**不要先定一个偏爱的专题，再把重大事件排除。** 同一事件的传闻、正式公告和后续合并，以最新可确认状态为准。
2. 用编辑标准判断哪些应展开、合读、简述或留档。在 `review.md` 留下主要取舍及理由；覆盖记录负责防遗漏，正文负责判断和阅读。完整资料不等于全量刊载。
3. 主编辑统一论点、篇幅与顺序。偏产品与技术，说明工作流、能力、成本、权限、可靠性或交付方式的变化；也审视关键人物的决策和长期影响。政府新闻只选重要少数国家／政府的关键动作，不凑国别，不平均分配厂商席位。
4. 事实与判断相邻但可区分。写清“发生了什么、改变了什么、我为何重视”；判断具体到产品、用户或技术选择，保留推断的证据边界。日期、预览／正式、地区、套餐、期限和自测条件只保留影响理解与使用的部分。
5. 不固定栏目、篇数、图片数或压缩比例。次要消息按共同问题合并，避免把删下的清单搬到另一栏，也避免在一段里塞回全部名字。成稿面向读者，不保留“应写成”“待主代理处理”等采编指令。

可将资料补充、配图和终审交给子代理并行处理，限定各自素材范围与文件归属；子代理提出证据和建议，主编辑负责最终取舍。不要把“每类交一份完整清单”当作成刊结构。

## 3. 配图、预览与修订

- 需要图片时优先选有解释价值的官方素材、真实界面或原理图；生成插图标明示意，不伪造产品界面、测试结果或数据。来源、用途和图注可记录在 `review.md` 或本期图片来源文件；不为每条消息强配图。
- 图片放在本期 `images/`，用 `![说明](images/文件名)` 引用。支持 PNG/JPEG/GIF/WebP，单图不超过 10MB。检查空白、截断和浏览器附加注记，保留原文与示例性质。
- 沿用 `DESIGN.md` 第10节及 `lib/publication*` 的正式模板。外部周刊只借鉴内容编排和阅读节奏，不据此替换共享样式。内部清单、研究稿和采编过程不进入正文。
- 调用 `npm run weekly:preview -- YYYY-MM-DD`；只生成文件可加 `--no-serve`。按 [report-preview](../report-preview/SKILL.md) 检查桌面、窄屏、目录、标题、图片、外链及草稿对应。不能完成的检查如实说明。
- 改草稿、图片或模板后重跑预览，重启旧预览服务，核对正在提供的页面确为最新文件。不要只改磁盘文件却继续让用户看旧服务捕获的 HTML。
- 交付本期预览和主要取舍，服务供用户审阅时保持运行。**用户查看并确认最新预览后**才进入周报发布；自动化检查和预览哈希都不能代替人的确认。

## 4. 按授权定稿与发布

进入本阶段时加载 [report-publish](../report-publish/SKILL.md)，沿用其 Git、替换和部署边界，不另造发布流程。

```bash
npm run weekly:finalize -- YYYY-MM-DD
npm run build
```

- 正式文件是 `weeklies/YYYY-MM-DD.html`，须与用户最后确认的预览完全一致。沿用脚本对正文、HTML、图片和模板的校验，不手改校验记录绕过检查。替换既有同一期需有相应授权，再用 `--replace`。
- 确认三个生成索引、本期入口和历史资源正常，私人素材及技能未进入 `dist/`。不手改索引，不提交 `dist/`。
- 提交、PR、推送按本次授权和当前分支执行，只包含本次交付路径，保留无关修改。`main`／`master` 推送会触发 Pages；不要因技能名称含“发布”就自动推送。
- 已授权上线时继续核对对应提交的 Actions 和线上本期／归档入口。失败或无法确认时停在真实状态，不把提交、PR 或推送说成已经上线。

## 交付

简明报告期次、成稿／预览或正式入口、核心编辑取舍和检查结果。涉及发布时再附提交、分支／PR、部署与线上链接，明确实际完成阶段。内容、图片或模板变动使旧确认失效；没有变动且已有明确确认时继续执行，不重复询问。
