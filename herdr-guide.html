01

—— OBJECT MODEL

先建立对象模型，再谈任何命令

Herdr 是为编程 Agent 设计的终端工作台：提供运行位置、状态视图和控制入口。它的布局分三层——所有命令都在操作这三层对象。

Workspace · 一个项目或工作上下文
Tab · 一组相关终端的布局
Pane运行 Codex
Pane测试 / 服务 / 其他 Agent

Agent = Herdr 在某个窗格中识别出的当前进程。窗格也可以只跑 shell、测试或开发服务器。

Herdr Session

保存后台服务、布局和仍在运行的终端。分离客户端、甚至重启服务器后，布局都能恢复。

Agent Session

保存对话上下文，由对应 Agent 自己管理。只有集成上报了有效的原生会话引用，Herdr 才能在服务器重启后恢复对应对话。

!分屏是布局操作；启动 Agent 是在窗格中运行进程。两个动作，两套命令——这是全文最重要的一句话。

安装、启动与集成

macOS / Linux / Windows 各一行。装完顺手装上你用的 Agent 集成，再验证版本。

$ brew install herdr $ curl -fsSL https://herdr.dev/install.sh | sh # Linux 或 macOS $ herdr integration install codex # 还有 pi / omp 等 $ herdr integration status $ herdr --version
认出三层布局与两种 Session

回到上面 01 的对象模型图：Workspace → Tab → Pane。再分清 Herdr Session（布局与进程）和 Agent Session（对话上下文）——恢复能力完全不同。

先学这些键位可练习

默认前缀键是 ctrl+b，先按前缀、松开、再按后续键——让 Herdr 的键位与 shell、编辑器、Agent TUI 的快捷键分开。也支持鼠标：单击切焦点，右键创建或分屏，拖动分隔线调整大小。

复制模式中 hjkl 移动，/ 或 ? 搜索，v 或空格开始选择，y 或回车复制，q 或 Esc 退出。复制模式不会暂停窗格进程。

到速查台 · 键位可以直接在页面上按真键练习。

案例：第一次启动并重连一个 Agent5 min
  1. 在普通终端确认版本并安装集成
  2. 在项目目录启动 Herdr
  3. 在窗格中运行 codex，提交一个小任务，确认侧边栏出现 Agent
  4. 按 ctrl+b 再按 q 分离客户端
  5. 回到外部普通终端再次运行 herdr，确认布局和进程仍然可见

0 / 6
五种 Agent 状态

Herdr 把状态汇总到窗格、标签页和工作区，帮你定位谁在运行、谁在等输入、谁可以审阅。完整五色卡见速查台 · 状态。

!done 和 idle 的差别只是标签页是否已被查看。显式执行 pane focus 或 agent focus 会标记已查看；只读输出不会。
×unknown 只表示生命周期判断不可靠，不表示任务成功完成。
状态来自哪里

每个窗格只有一个状态权威：Pi、OMP 等有完整生命周期上报的 Agent 由集成决定状态；Codex、Claude Code 等主要靠前台进程和终端底部缓冲区的屏幕规则。不受支持的 Agent 仍能作为普通终端进程运行，只是状态可能不完整。

!对屏幕检测型 Agent，blocked 的判断刻意从严——未识别的新提示界面可能暂时显示为 idle。Agent 若运行在 Herdr 窗格内的 tmux、虚拟机或沙箱包装器之后，Herdr 可能看不到真实前台进程。

排查时直接看解释结果：

$ herdr agent explain reviewer --json # 输出最终状态、清单来源、匹配规则和回退原因
集成与 Skill 的分工
能力作用
集成上报生命周期状态、原生会话身份，或两者之一
Skill教 Agent 如何操作 Herdr 的布局、窗格和 Agent 命令
$ npx skills add herdrdev/herdr --skill herdr -g # -g 全局；只用于当前项目时省略 $ herdr --skill # 已装 Herdr：输出与当前二进制匹配的内置版本
×执行 Herdr 控制命令的 Agent 必须运行在 Herdr 管理的窗格中。控制前先检查 test "${HERDR_ENV:-}" = 1；检查失败就停止控制操作，从 Herdr 窗格重新启动 Agent。不要手工设置 HERDR_ENV 绕过检查。
派工四步：分屏、启动、提交、读取核心

最省事的方式是把位置、角色、任务和边界一次说清：

使用 Herdr Skill，在当前项目目录的相邻窗格启动一个 Codex Reviewer。 保持当前焦点。让它只读审阅当前 diff，对照需求检查遗漏和错误路径， 报告文件、行号、触发条件与影响，不修改文件。 等待状态变化后读取结果；遇到 blocked，先说明它在等待什么。

对应的 CLI 流程：

$ test "${HERDR_ENV:-}" = 1 $ split=$(herdr pane split --current --direction right --cwd "$PWD" --no-focus) $ review_pane=$(printf '%s\n' "$split" | jq -r '.result.pane.pane_id') $ herdr agent start reviewer --kind codex --pane "$review_pane" $ herdr agent prompt reviewer \ "只读审阅当前 git diff，列出文件、行号、触发条件与影响；不修改文件。" \ --wait --timeout 60000 $ herdr agent get reviewer $ herdr agent read reviewer --source recent-unwrapped --lines 120
×创建命令返回 JSON，必须从响应读取新窗格 ID，不能按侧边栏顺序猜测。窗格移动后 ID 可能变化，继续使用新响应中的 ID。
!agent prompt --wait 默认等待稳定的 idle、done 或 blocked。blocked 不是完成，等待超时也不表示提示没有发出——超时后先 agent get 和 agent read，避免重复提交同一任务。
窗格命令 vs Agent 命令
目标使用的命令
运行 shell 命令pane run
发送纯文本或按键pane send-text、pane send-keys
等待文本或正则pane wait-output
启动受支持的 Agentagent start
提交提示并等待生命周期状态agent prompt
操作 Agent 的交互界面agent send-keys
等待精确 Agent 状态agent wait

对 shell、测试、服务器和 CI 监视器用窗格命令；需要识别 Agent 身份或生命周期状态时用 Agent 命令。

!pane wait-output 只匹配终端文本，不解释生命周期，已有文本也可能立即命中；agent wait 观察当前状态，已匹配会立即返回。两个等待命令省略 --timeout 都会无限等待。
读取输出 + 案例：等待审批
来源适用场景
visible当前渲染的屏幕，适合处理交互界面
recent保留终端软换行的最近回滚内容
recent-unwrapped合并软换行，适合日志和长回复
detection状态检测使用的底部纯文本快照

全屏 Agent（Claude Code、OpenCode 等）可能把历史放在备用屏幕：读取不完整时先加 --lines；仍缺失就等 Agent 空闲后再读，或让它把完整结果写入 Markdown 文件并返回路径。

$ herdr agent wait reviewer --until blocked --timeout 120000 $ herdr agent read reviewer --source recent-unwrapped --lines 80 $ herdr agent send-keys reviewer esc

布局、分离与恢复

离开时按 ctrl+b 再按 q 分离，返回时在外部终端重新运行 herdr。不要在 Herdr 窗格中嵌套启动不带参数的 herdr。服务器重启后，Herdr 恢复保存的布局，以及已上报原生会话引用的 Agent 对话；普通测试、开发服务器和没有会话引用的 Agent 需要重新启动。

×只有确实要结束服务器及其全部窗格进程时，才运行 herdr server stop。
# 常见布局命令，按对象分组 $ herdr workspace list $ herdr tab list $ herdr pane list $ herdr pane split --current --direction right --cwd "$PWD" --no-focus
远程机器与 Git Worktree

用 --remote 通过 SSH 连接远程 Herdr 服务器；machine 命令组管理多机；worktree 命令组为任务开出隔离的 Git 工作树。

$ herdr --remote devbox # SSH 连接远程服务器 $ herdr machine add devbox --label "开发机" $ herdr worktree create --branch feat/review --label "审阅工作树"
以后不用背：自助速查

CLI 通过与集成和 Agent 相同的本地 socket API 与服务器通信，大多数命令输出 JSON——脚本里直接用。完整选项以 herdr <group> --help 为准；本页速查台已按命令组建好索引， 随时呼出搜索。
