配置模型角色 MODEL ROLES

模型名称会变，角色相对稳定。模型角色用于将不同类型的任务映射到不同模型。不配置角色也能运行；需要稳定控制质量、延迟、成本或服务商选择时，再固定角色。

config.yml
modelRoles:
  default: anthropic/claude-sonnet-4-5
  smol:    anthropic/claude-haiku-4-5
  slow:    anthropic/claude-opus-4-6:high
  plan:    openai/gpt-5.3-codex:high
  commit:  anthropic/claude-haiku-4-5

这份配置表达不同任务之间的成本分配：

角色任务
default常规实现、代码问答、主会话默认
smol分类、机械修改、短摘要
slow复杂故障、架构权衡、高风险 Review
plan多文件任务的只读规划
commit提交信息等短而稳定的输出

会话是一棵树 SESSION TREE

OMP 会话按工作目录归类，并以 JSONL 文件保存。每个回合都记录父节点，因此可以从任意历史回合继续，并形成多条互不覆盖的分支。已完成的回合会自动保存到本地；如果 OMP 异常退出，通常只会丢失尚未完成的末尾响应。

如何选择会话操作

目标操作结果
开始一个无关的新任务/new创建新会话
继续其他历史会话/resume选择并打开已有会话
浏览或比较同一问题的多种方案/tree在当前会话文件内切换或创建分支
从较早回合创建替代延续/branch按设置的分支行为创建替代延续
为大型或高风险实验建立隔离副本/fork将当前会话克隆为独立文件
重命名会话/rename <title>设置容易识别的名称

/tree 会显示当前会话的树状结构。选择较早的用户消息并重新提交后，OMP 会在原路径旁创建新分支，同时保留原路径。

如果只需要比较思路，使用 /tree；如果需要明确的检查点或完全隔离的实验，使用 /fork。

上下文、压缩与交接 CONTEXT & HANDOFF

手动恢复路径

情况命令结果
会话健康，但需要更多空间或想强调某些决策/compact [focus]旧上下文变摘要/归档，出现分界线
下一阶段需要目标、决策、进展、下一步的结构化记录/handoff [focus]生成交接文档并就地替换旧活跃上下文
大量命令/文件/生成代码/图像/思考块挤占对话/shake [elide|images|thinking]用占位符替换重内容；elide 会存工件可恢复

/compact 一次性方法：/compact soft [focus]（模型摘要）、/compact remote [focus]（服务商原生 OpenAI 兼容压缩，回退 soft）、/compact snapcompact（本地图像归档，不接受焦点文本）。手动 /compact 在自动压缩禁用时仍有效；有响应运行时先中止该响应。

/handoff 尽管叫交接，当前版本就地压缩当前会话：不会开启后续会话，默认也不保存 Markdown 文件（compaction.handoffSaveToDisk: true 才会把自动交接存盘）。运行前等当前响应完成或中止它。

/shake 默认 elide：用简短占位符替换命令/搜索/文件读取输出与大围栏块；持久化会话中把被移除区域存为工件，占位符带 artifact://… 恢复引用，之后重要可让 omp 按引用恢复。/shake images、/shake thinking 不创建恢复工件。Nothing to shake 是成功空操作。

记忆 MEMORY BACKENDS

记忆让 omp 无需反复重述仓库约定、架构决策、审查偏好等持久事实就能接续之前的工作。它与压缩是两回事：压缩只缩短单个会话，记忆影响之后的会话。

记忆默认关闭：打开 /settings → Memory 挑一个后端；要可搜索的本机记忆从 mnemopi 开始，要自动生成项目摘要用 local，已在运行 Hindsight 服务就选 hindsight。

选择一个后端

后端适用场景存储与默认作用域重要取舍
off（默认）不需要跨会话知识无记忆存储关闭记忆不影响已有会话记录
local定期把已持久化会话提炼成项目指导本机生成、按工作目录隔离的文件（~/.omp/agent/memories/<encoded-project>/）批式摘要流水线，不是可搜索存储；无法查阅或遗忘单条事实
mnemopi提示词驱动的「记住、回忆、遗忘」，无需记忆服务器本地 SQLite（~/.omp/agent/memories/mnemopi/），默认 per-project默认 smol LLM 抽取可能把工作发给模型服务商；llmMode: none 可避免
hindsight远程记忆库、共享基础设施、心智模型Hindsight 服务器，默认 per-project-taggedautoRetain 默认开启，对话文本离开本机
bash
omp config set memory.backend local   # 或 mnemopi / hindsight
omp config get memory.backend

/settings 写入全局配置并在保存时切换后端；shell/YAML 改动对新启动进程生效。只想针对一个仓库时把相同键放进 <repo>/.omp/config.yml（项目覆盖全局）。

隐私、作用域与默认值

  • Off 只关记忆处理，不禁用普通会话持久化；记忆命令不删除 ~/.omp/agent/sessions/ 下的文件。
  • Local 生成产物存本地；抽取与整合阶段使用你配置的模型角色，过去的会话文本仍可能发给该模型服务商；输出会过滤常见 token 与密钥模式，但不要故意让 omp 记住机密。
  • Mnemopi 的 SQLite 在本地；本地嵌入可能下载并运行嵌入模型；默认 llmMode: smol 用在线 tiny/smol 模型做 LLM 抽取，不想要任何 LLM 记忆处理就用 llmMode: none。
  • Hindsight 在 autoRetain: true（默认）时每三个用户回合及会话边界发送用户和助手文本（省略工具调用、工具结果和思考块）；召回与合成查询也发往该服务器。
  • 关闭某个后端不删除它的存储——切换可逆，但目标是删除时必须另外清理。

在累积敏感数据前先选定作用域（客户工作等硬边界场景优先 per-project）：

作用域MnemopiHindsight
global一个本地记忆库所有项目可见一个远程记忆库所有项目可见
per-project按绝对工作目录派生隔离库（默认）按仓库名隔离；同仓库 worktree 共享主检出名称
per-project-tagged写项目库、召回合并共享全局库带项目标签数据入共享库、召回合并全局（默认）

在对话中使用记忆

Mnemopi 或 Hindsight 用普通提示词即可：

prompt
请记住这个仓库使用 pnpm 和 Node 22。
prompt
在改动身份认证之前，先回忆一下我们当初为什么否决了会话 cookie。

Mnemopi 还能编辑、遗忘或使一条可编辑记忆失效（「忘掉那条说发布在周五的记忆」「把发布约定更新为 CI 变绿之后发布」）。描述可能匹配多条时，先让 omp 展示候选再改。Mnemopi 的「事实表」行只读；彻底移除时直接清空对应作用域记忆库。Hindsight 不暴露单条编辑，用 Hindsight UI 做记录级查阅/删除。

local 后端不同：自动摘要符合条件的已持久化会话，启动时注入静态 Memory Guidance 块；「记住这个」不保证单条写入。它适合让反复出现的项目知识从已完成工作中浮现出来。

召回或摘要出来的记忆是背景上下文，不是指令——与当前提示词或当前仓库状态冲突时，以后者为准。

最小配置示例

Mnemopi 面向隐私的配置（仅全文搜索、不做 LLM 抽取）：

config.yml
memory:
  backend: mnemopi
mnemopi:
  scoping: per-project
  noEmbeddings: true
  llmMode: none

Hindsight：本地免认证服务器只需 memory.backend: hindsight（内置 URL http://localhost:8888）；云端/认证部署设 hindsight.apiUrl 与 hindsight.scoping，token 用 HINDSIGHT_API_TOKEN 环境变量（HINDSIGHT_* 覆盖对应 hindsight.* 设置）。

排障

  • local 启用后 /memory view 为空 → local 只处理已持久化主会话、跳过最近 12 小时活跃会话，/memory enqueue 后正常退出重启，并确认 default/smol 角色有凭据；
  • mnemopi 不记忆不召回 → /memory diagnose、试 noEmbeddings: true 或 llmMode: none 隔离；
  • hindsight 无反应 → 确认 omp config get memory.backend 与 hindsight.apiUrl 后 /memory diagnose；
  • 跨项目串味 → 检查 scoping，切 per-project 后另外清理旧数据；
  • 记忆过期 → 对照当前仓库核实，更新或遗忘。

工作模式 FIVE MODES

1. /plan：先只读规划，再决定是否执行

计划模式把下一轮交给独立的 plan 角色模型，并过滤写入类工具。适合多文件修改、执行顺序不明显的重构和高风险设计。

prompt
/plan 把 src/importer.ts 改成流式处理，并迁移所有调用方

计划批准后通常有三种交接方式：

  • 批准并执行：清除计划讨论，只交付最终计划；
  • 批准并保留上下文：执行者看到完整讨论；
  • 批准并压缩上下文：把讨论总结后继续。

单文件小改动不值得额外走计划轮次。

计划的价值来自降低执行风险，不来自形式上的「先写一份计划」。

2. /goal：让 Agent 围绕验收目标持续推进

目标模式适合跨多轮、下一步可推导、但总工作量未知的任务，例如大规模迁移或持续修复测试。

prompt
/goal 将导入器改造成流式处理，更新所有调用方，并用现有测试证明兼容
/goal budget 200000

目标模式应有预算。模型只有在能把每项交付映射到文件或命令证据时，才应调用完成。子命令：/goal set/show/pause/resume/drop、/goal budget <N|off>。

预算耗尽表示「停止扩张并汇报现状」，不等于任务完成。

3. /loop：重复同一提示词固定次数或固定时长

prompt
/loop 10
修复测试套件中下一个失败用例，并在每轮结束后重新运行相关测试

/loop 没有目标语义，不会判断整体工作是否真的完成。它适合机械迭代，不适合开放式交付。形式：/loop（无限，下一条提示成为循环提示）、/loop <prompt>、/loop <N> [prompt]（首个回合后再自动重放 N 次）、/loop <duration> [prompt]（90s、10 min、1h30m；到墙钟截止停止）。迭代中按 esc 中止当前回合，Loop 仍保持启用；迭代间按 esc 暂停 Loop，并丢弃已捕获的提示。再运行 /loop 会完全禁用循环；计数或时长耗尽时，循环会自动禁用并说明原因。loop.mode 默认 prompt（同一会话延续），compact 每次重放前压缩，reset 每次重放前新会话。

4. /background：让当前任务脱离 TUI 继续运行

运行中的会话可用 /background（或 /bg）分离，随后通过 omp -c 重新接入。它常与有明确边界的 /loop 或长时间任务配合。

分离不等于验证。回来后仍要检查产物、退出状态和测试结果。

5. /force 与 /fast

  • /force <tool> [prompt]：只在下一轮锁定指定工具一次（/force read 或 /force:read 等价），用于模型持续选择错误工具的情况；下一次模型调用必须调用该工具一次，之后回合恢复正常。工具不活跃或模型无法强制时失败而不是猜测。
  • /fast：对支持的 OpenAI 模型切换优先服务层（service_tier=priority），通常以更高费用换更低延迟。/fast on/off/status，裸 /fast 切换；按模型家族独立记忆、会话持久化；计入 premium-request 计量。
/force 不能修复模糊需求，/fast 不能修复糟糕的模型路由。

Prewalk：规划与实现交接 PREWALK

Prewalk 在同一会话中先用较强模型理解仓库、识别风险并整理 todo，再把后续实现交给更快或更便宜的目标模型。对话、上下文、todo 和已有改动保持不变。

工作形态建议
前期调查复杂，后续是批量修改、例行测试或机械编辑使用 Prewalk
需要持续设计、细致调试，或涉及安全和隐藏约束让能力足够的模型完成全程
修改很小且路径明确直接使用一个快速模型

目标模型应能按 todo 继续执行，无需重新做主要设计决策。

启用与交接

Prewalk 默认关闭：

sh
omp --model @slow --prewalk-into @smol # 强模型规划，快速模型实现
omp --prewalk                          # 本次会话启用，目标为 @smol
omp config set prewalk.enabled true    # 每次新会话启用
omp --no-prewalk                       # 本次会话不交接

--prewalk-into 支持角色别名或 provider/model-id，可带思考等级。--no-prewalk 不能与 --prewalk 或 --prewalk-into 同时使用。恢复已有会话时，需要显式传入 --prewalk。

todo 可用且第一次文件编辑完成后，OMP 才会交接；第一次编辑仍由起始模型完成。只读操作、搜索和讨论不会触发交接。状态栏显示 Armed 表示等待交接，Switched 表示已经切换，Nothing to switch 表示目标模型与当前模型相同。

Prewalk 每次只交接一次。会话内可运行不带参数的 /prewalk 布防；默认目标为 @smol，已布防时保留现有目标。Prewalk 只影响主会话；子智能体需要单独配置。

Vibe：协调多个工作者 VIBE

Vibe 适合能拆成独立工作流的任务，例如前后端并行修改、迁移与审查分工，或按文件划分的大规模清理。主会话负责拆分和验收，工作者负责搜索、编辑、运行命令和构建。小型或必须顺序执行的修改直接在主会话完成。

prompt
/vibe 把这个版本拆分成彼此独立的工作流。让一个 fast 工作者更新那些机械性的调用点，再让一个 good 工作者审查迁移和兼容性风险。报告完成之前先验证两者。

核心操作

  1. 运行 /vibe <任务说明>，或先运行 /vibe 再描述任务。
  2. 为每个工作者写清范围、文件、限制和验收标准。工作者不会继承主会话的对话。
  3. 根据工作类型选择工作者：
工作者适用任务
fast批量重命名、直接测试、样板代码、数据收集等机械工作
good设计、调试、审查、有风险或跨多文件的改动
  1. fast 遇到架构决策或持续卡住时，把决策或审查交给 good。
  2. 主会话核验各工作者的改动和测试结果后，再报告完成。
  3. 再次运行 /vibe 退出。OMP 会停止剩余工作者，并恢复进入 Vibe 前启用的工具。

状态栏显示 Vibe 时表示模式已启用。工作者可以读写文件和运行命令，并会额外消耗模型用量。启用前保存重要工作，划分互不重叠的文件范围，排除凭据和敏感路径，并限制不应使用的工具。

不要让多个工作者同时操作同一个 Git 状态。
config.yml
modelRoles:
  fast_worker: openai/gpt-5-mini
  good_worker: anthropic/claude-sonnet-4-5:high

task:
  agentModelOverrides:
    sonic: "@fast_worker"
    task: "@good_worker"

子智能体与委托 SUB-AGENTS

子智能体适合可独立推进的研究、实现和审查任务。小型串行修改、多人持续编辑同一文件，或每一步都依赖上一步结果的工作，应留在主会话。

核心操作

1. 根据任务选择专家：

专家用途
scout只读探索仓库并汇总发现
designerUI/UX、无障碍和视觉实现
reviewer正确性与质量审查
security-reviewer只读安全分析
librarian核实外部库和 API
task通用多步骤任务
sonic机械编辑或数据采集
  1. 用自然语言委托，例如「用 librarian 核实上游的重试语义」。名称区分大小写；运行 /agents 查看可用专家及其状态。
  2. 提供自包含简报，写清目标、范围、文件、限制和验收标准。子智能体不会继承主会话的对话。
  3. 为并行编辑者划分互不重叠的文件范围，由主会话统一审查和集成结果。

查看与隔离

智能体中心的打开方式见「编辑器常用能力与键位表」。在中心内，按 j、k 或方向键选择工作者，按 enter 查看记录，按 r 恢复停驻的工作者，按 x 终止并释放实例，按 esc 关闭界面。/jobs 可查看后台任务摘要。

子智能体默认共享主会话的检出。需要隔离编辑时，在 /settings → Tasks → Isolation 中选择 Auto；此模式要求 Git 仓库，成功改动默认以补丁应用到主检出。隔离工作区不能替代安全沙箱，计划模式下也不可用。

每个子智能体都会单独消耗模型用量。从少量工作者开始，限制任务和工具范围，不提供无关密钥，并停止已经过时的任务。

顾问 ADVISOR

顾问（Advisor）使用独立模型，在主会话进行期间检查遗漏需求、风险、验证不足和不必要的复杂度。它适合耗时较长、高风险或仓库不熟悉的任务；普通小修改通常不值得额外的模型用量。

启用与控制

在 ~/.omp/agent/config.yml 中配置默认顾问：

config.yml
modelRoles:
  advisor: anthropic/claude-sonnet-4-5:medium

advisor:
  enabled: true

未配置 WATCHDOG.yml 顾问阵容时，OMP 使用 modelRoles.advisor 创建默认顾问；该角色必须能解析为已认证的可用模型。会话中使用以下命令：

命令作用
/advisor切换所有已配置顾问
/advisor on、/advisor off本次会话启用或停用，不修改配置文件
/advisor status查看模型、状态、上下文、用量和成本
/advisor configure在 TUI 中编辑项目或用户级 WATCHDOG.yml

处理顾问提示

严重程度含义
nit清理、简化或低风险边界问题
concern实质风险、遗漏约束或可能走偏
blocker继续执行很可能浪费工作或产生错误结果

只有 blocker 可以打断正在进行的工作。顾问建议不会自动执行；主会话仍需根据任务要求核实和决定。提示噪音过多时，关闭顾问或收窄关注点。

将项目专属的架构边界、危险 API、常见失败模式和验收证据写入 .omp/WATCHDOG.md；通用规则可写入 ~/.omp/agent/WATCHDOG.md。规则必须具体，并能改变审查判断。

启用顾问会把提示、主智能体输出、推理和工具结果发送给顾问模型服务商。只选择获准处理当前仓库内容的模型和服务商。

配置多个专家顾问

WATCHDOG.yml/WATCHDOG.yaml 声明阵容，一旦发现任何阵容条目就取代单一默认顾问：

WATCHDOG.yml
advisors:
  - name: Architecture

典型案例：推进一次多文件重构 CASE STUDY

场景：导入器需要改成流式处理，调用方较多，部分工作可以并行，但最终必须由主会话统一验证。

1. 新建干净会话并先做只读规划：

prompt
/new
/plan 把 src/importer.ts 改成流式处理。列出所有调用方、兼容性约束、迁移顺序和验证命令；不要修改文件。

2. 审阅计划后，设置有边界的持续目标：

prompt
/goal 将导入器改造成流式处理，更新所有调用方，并用现有测试证明兼容
/goal budget 200000

3. 开始实现前用 /context 记录窗口余量。若输出过重，先运行 /shake；若历史已经很长，运行 /compact 保留接口约束、迁移进度、未完成项和测试结果。

4. 只有在调用方之间确实互不重叠时才启用 /vibe，为每个工作者写明目录归属、不得修改的接口、交付物和验证命令。共享检出时避免多个工作者编辑同一文件；需要更强隔离时先配置 Tasks → Isolation。

5. 用 /agents 查看工作者状态，读取每个工作者的改动和报告。不要把 idle 或 completed 当成组合行为已验证；由主会话运行相关测试和实际 smoke test。

6. 阶段完成后运行 /handoff 保留已完成迁移、剩余调用方、测试结果和下一步，让当前会话留下可恢复的交接状态。

审查改动：/review REVIEW

在合并 PR、完成高风险重构或准备提交前运行 /review。它只检查选定差异引入的问题，不修改文件。

  1. 确认审查范围。未跟踪文件不在 Git diff 中，需要先暂存。
  2. 运行审查，并写明具体风险：
prompt
/review focus on partial writes, retries, and idempotency

审查 GitHub PR 时，可以直接提供完整 PR URL。需要先安装并登录 gh。

  1. 逐条核对发现项引用的代码和触发条件。
  2. 修复成立的问题，运行相关测试，再次审查。

发现项的优先级含义：

优先级处理建议
P0立即停止发布或运行
P1合并前修复
P2核对边界条件并安排修复
P3按价值决定是否处理
置信度表示发现项成立的可能性，不表示严重程度。审查结论为「正确」只表示本次差异中没有确认的阻断问题，不能证明代码没有缺陷。

安全扫描：/security SECURITY

/security 用于认证、授权、解析器、网络边界和发布前的漏洞检查。它不是通用代码审查，也不能证明仓库不存在漏洞。

使用前确认：

  • 当前目录是 Git 仓库。
  • 已选择活动模型，并为模型提供商保存 OAuth 登录。
  • 已接受相关仓库内容会发送给模型服务商。--path 只限制审查和报告范围，不构成保密边界。
  • 已在 /settings → Tools → Security 开启功能，或运行：
sh
omp config set security.enabled true

推荐流程：

1. 创建窄范围计划：

prompt
/security plan --path src/auth --exclude src/auth/fixtures --knowledge-base SECURITY.md

2. 使用返回的计划 ID 启动扫描：

prompt
/security scan secplan_…
  1. 用 /security status 等待状态进入 completed，再运行 /security show <scan-id>。
  2. 对重要发现项运行 /security validate <scan-id> <finding-id>。模型校验仍需人工判断。
  3. 记录处置结论。非 open 状态必须填写理由。
  4. 修复后创建新计划并重新扫描，再用 /security compare <before> <after> 对比。partial 或 failed 不能证明问题已经解决。

计划会固定仓库快照、范围、模型、账户和知识库文件。代码、范围或凭据变化后，旧计划会失效；重新创建计划，不要复用旧 ID。详细命令和状态见附录。

发布前的最小流程 SHIP IT

/review→ 修复成立的发现项并运行相关测试→ 高风险改动再执行 /security plan 和 /security scan→ 需要跨文件改名时先让 LSP 展示引用和预览→ git add 指定文件→ omp commit --dry-run→ 确认后运行 omp commit

每次代码或扫描范围发生变化后，重新运行与改动相匹配的验证。

安全扫描、代码审查和提交预览都不能替代测试。

alt+shift+p切换计划模式

会话与上下文 SESSION

会话按工作目录归类为 JSONL；回合记录父节点，可分支。

命令作用
/new创建新会话

/branch从较早回合创建替代延续
/fork克隆为独立会话文件（隔离实验/检查点）
/rename <title>重命名会话
/compact [focus]压缩旧上下文；soft 模型摘要 / remote 服务商压缩 / snapcompact 图像归档
/handoff [focus]生成交接并就地压缩当前会话；默认不存盘（compaction.handoffSaveToDisk）
/shake [elide|images|thinking]占位符替换重内容；elide 存 artifact:// 工件可恢复
/context查看上下文占用
/usage查看额度和速率限制

附录：排障与高级配置

安全扫描的状态与产物 SCAN LIFECYCLE

queued→ preparing→ reviewing→ publishing→ completed

partial、cancelled 和 failed 也是终止状态。取消请求成功后，仍要等状态变为 cancelled。

本地扫描输出包含 scan.json、findings.json、report.md、results.sarif 和脱敏的 provenance.json。进程重启后，运行中的原生扫描不能恢复；检查状态后创建新计划。禁用安全扫描不会删除已保存的结果。
