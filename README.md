# my-reports
AI-generated report

## 周简报

需要 Node.js 24。安装依赖：`npm ci`。构建：`npm run build`，生成三个索引，并把允许公开的站点内容打包到 `dist/`。GitHub Pages 仅上传该目录。测试：`npm test`。

### 每周编辑

每周开始先运行 `npm run weekly:init -- 2026-11-08` 创建本地工作目录。日期必须是该周周日；已有素材不会覆盖。

1. **收集原文**：编辑 `.local/weeklies/2026-11-08/materials.md`。用二级标题（`##`）划分栏目，三级标题（`###`）标记栏目内各条素材。只有一篇长文的栏目也可以直接在二级标题下粘贴正文。日报内容由你选定后放入素材文件。来源核对由你自行处理，不属于流程或发布前置条件。
2. **脚本整理草稿**：`npm run weekly:draft -- 2026-11-08`。按素材中的栏目顺序组织正文，合并同名栏目，删除完全重复的条目；不根据链接或主题相似度删文。同链接但正文不同会保留。输出同目录 `draft.md` 和整理记录 `draft-report.json`，素材原文件保持不动。你直接编辑草稿中的内容细节。人工修改后的草稿受覆盖保护；确认重新整理时用 `--replace`，脚本会先保存旧稿备份。
3. **脚本预览**：`npm run weekly:preview -- 2026-11-08`。打开命令输出的本机地址审阅。直接修改 Markdown 后，停止并重新运行预览；Ctrl+C 停止服务。
4. **脚本定稿**：确认预览后运行 `npm run weekly:finalize -- 2026-11-08`。正式 HTML 存入 `weeklies/`。同一期修订需显式添加 `--replace`；草稿或预览变化后必须重新预览。
5. **发布**：`npm run build` 检查归档，再按现有 Git 提交、推送流程发布。定稿不会自动提交或推送。

正文使用一个一级标题、二级栏目标题、三级条目标题。可按好文章、开源项目、一周动态分组，按实际素材决定条数，空栏目删除。Agent 仅协助去重和组织栏目，允许删除、重排和加标题，保留被采用正文的原文措辞、数字和链接；内容细节由你自行编辑。整理脚本不改写、概括正文，也不额外撰写导读、摘要、推荐理由或核对来源。你提供的导读或备注可以作为原文采用。

Markdown 支持列表、引用、代码块、表格；原始 HTML 不执行。图片放在本期工作目录的 `images/` 下，在草稿相关段落后插入 `![图片说明](images/文件名.png)`；支持 PNG、JPEG、GIF、WebP，单图最多 10 MB。预览直接内嵌本地图片，定稿后仍是自包含 HTML；修改图片后须重新预览。远程图片需先自行下载到该目录。日报来源链接使用完整网站 URL。正文只有 Markdown 一份编辑来源，无须维护 JSON 正文。

素材、草稿和审阅说明仅本地保存；已发布 HTML 是公开归档。构建不会调用模型、抓取外网或重新改写正文。请勿把私人草稿存入 reports、digests 或 weeklies 的正式发布文件。
