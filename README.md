# my-reports
AI-generated report

## 周简报

需要 Node.js 24。安装依赖：`npm ci`。构建：`npm run build`，生成三个索引，并把允许公开的站点内容打包到 `dist/`。GitHub Pages 仅上传该目录。测试：`npm test`。

### 每周编辑

1. `npm run weekly:init -- 2026-11-08`，日期必须是该周周日，按北京时间周一至周日归档。
2. 编辑 `.local/weeklies/2026-11-08/materials.md`，在文章、项目栏目下添加链接，可附收藏理由与真实使用感受。该目录被 Git 忽略，需要自行备份。
3. 在项目聊天中要求 Agent：“根据本周素材和 11 月 2–8 日日报起草 2026-11-08 周简报”。Agent 核对原始来源，优先保留手选内容，合并重复项，把正文写入同目录 `draft.md`，核验情况写入 `review.md`。
4. `npm run weekly:preview -- 2026-11-08`，打开命令输出的本机地址审阅。可直接修改 Markdown，或在聊天中提出修改；改后停止服务并重新运行。Ctrl+C 停止预览服务。
5. 确认当前预览后执行 `npm run weekly:finalize -- 2026-11-08`。正式 HTML 存入 `weeklies/`；同一期修订需显式添加 `--replace`。草稿或预览被修改后必须重新预览。
6. `npm run build` 检查归档，按现有 Git 提交、推送流程发布。定稿不会自动提交或推送。

正文使用一个一级标题、二级栏目标题、三级条目标题。建议栏目：本周导读（100–200 字）、好文章（3–5 篇）、开源项目（3–5 个）、一周动态（0–2 条）；目标 8–12 条，不凑数量。空栏目直接删除。每条包含原文链接、摘要、推荐理由，项目注明适用人群与限制。没有实测依据不写亲身体验；无法读取原文不凭标题编摘要，写进审阅说明。列出缺失日报、未采用的手选素材及原因。

Markdown 支持列表、引用、代码块、表格；原始 HTML 不执行，首版图片显示为来源提示。日报来源链接使用完整网站 URL。正文只有 Markdown 一份编辑来源，无须维护 JSON 正文。

素材、草稿和审阅说明仅本地保存；已发布 HTML 是公开归档。构建不会调用模型、抓取外网或重新改写正文。请勿把私人草稿存入 reports、digests 或 weeklies 的正式发布文件。
