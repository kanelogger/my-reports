# 报告馆

个人报告、日报与周报的静态归档。Node.js 24，使用 `npm ci` 安装依赖。`npm run build` 生成三个索引并打包到 `dist/`；GitHub Pages 只发布该目录。

## 四个功能 Skill

采集由你负责。Agent 按功能处理已有报告或你提供的素材，四个 Skill 位于 `.agents/skills/`，可以单独调用，也可以按本次要求连续执行。

| Skill | 职责 | 完成时交付 |
| --- | --- | --- |
| [report-import](.agents/skills/report-import/SKILL.md) | 导入报告或素材，检查目录、入口和资源完整性 | 报告入口或本期私人素材路径 |
| [report-organize](.agents/skills/report-organize/SKILL.md) | 分类、重排、拟标题，默认保留正文 | 草稿及整理说明 |
| [report-preview](.agents/skills/report-preview/SKILL.md) | 生成预览，检查排版、导航、链接和资源 | 预览地址或文件及检查结果 |
| [report-publish](.agents/skills/report-publish/SKILL.md) | 定稿、构建、提交、发布并核对部署结果 | 正式文件、提交及线上结果 |

三类内容组合使用：

- **报告**：导入 → 预览 → 发布。完整报告保留原有内容与设计，明确要求整理时才调用整理 Skill。
- **日报**：导入你收集的消息 → 按需整理 → 预览 → 发布。
- **周报**：导入资料 → 整理 → 预览与修改 → 你确认 → 发布。

只要求导入、整理或预览时，到对应步骤结束，不会自动定稿、提交或推送。已有完整草稿可直接预览，已有确认版本可直接发布。一次要求“导入并发布”可以连续执行所需功能；日报明确授权直接发布时，Agent 仍生成并检查预览，无需再次询问。周报必须经过你查看并确认最新预览，不能用事前的“直接发布”跳过这一步。

### 导入与内容整理

- 单页 HTML 放在 `reports/` 下；多页报告放在 `reports/<目录>/`，必须有入口 `index.html`。保留原有样式、子页面与资源，相对路径必须可用。新报告建议使用带日期和清晰标题的文件名；索引规则见 `AGENTS.md`「如何添加新报告」。
- 日报素材放在 `.local/digests/YYYY-MM-DD/`，周报素材放在 `.local/weeklies/YYYY-MM-DD/`。原始素材保留在 `materials.md` 或原文件中，整理后的正文放在 `draft.md`；已完成的 Markdown 可直接作为草稿导入。
- 导入保留源文件及已有人工修改；遇到目标重名，先展示差异并确定保留、另存或覆盖，获得覆盖授权后再执行。
- 整理默认只分类、重排、拟标题，保留正文措辞、数字、链接、引用、代码、表格、图片及限定条件。原文标题与来源信息保留，可另拟展示标题。删减、去重、合并正文、改写、概括或补写需明确授权；仅说“整理”不包含这些操作。
- 周报保留原始资料，并在本期 `review.md` 中记录分类、顺序和标题调整，供你对照修改。来源核对由你处理，不属于发布前置条件；Agent 不补造来源或采集新消息。

## 日报与周报

你负责收集资料并决定正文内容，可以自己编辑，也可以调用 `report-organize` 分类、重排和拟标题。以下脚本由相应 Skill 调用：导入时初始化，预览时生成页面，发布时定稿与构建。脚本按已选定的 **A · 纸刊编辑** 样式生成 HTML，保留正文、数字、链接和图片。

两种刊物共用一份模板：米白纸色、宋体标题、分章配色、目录、字号调节、专注阅读、手机章节导航与打印样式。定稿产物为自包含 HTML，字体子集和本地图片均内嵌，阅读不依赖外部脚本或字体服务。

### 日报

以 2026-11-05 为例，换成你要制作的真实日期：

```bash
npm run daily:init -- 2026-11-05
```

将已收集的消息导入 `.local/digests/2026-11-05/`，按需整理并编辑 `draft.md`，完成后预览：

```bash
npm run daily:preview -- 2026-11-05
```

打开命令输出的本机地址，确认本期内容与排版，再定稿：

```bash
npm run daily:finalize -- 2026-11-05
npm run build
```

正式文件为 `digests/2026-11-05.html`。构建后进入日报归档。

### 周简报

使用该周周日作为日期。以 2026-11-08 为例：

```bash
npm run weekly:init -- 2026-11-08
```

先在 `.local/weeklies/2026-11-08/` 保留原始资料，分类、重排和拟标题后写入 `draft.md`。已有完整草稿时直接使用。你可自行修改草稿，也可要求 Agent 按上述边界调整，然后预览：

```bash
npm run weekly:preview -- 2026-11-08
```

你查看并确认最新预览后，再定稿、构建：

```bash
npm run weekly:finalize -- 2026-11-08
npm run build
```

正式文件为 `weeklies/2026-11-08.html`，日期区间按北京时间周一至周日显示。

### Markdown 格式

一个一级标题表示本期标题，二级标题划分章节，三级标题标记文章、人物或项目。栏目按你的内容决定，空栏目自动隐藏。

```markdown
# 本周简报

## 好文章

### 原文标题

粘贴你已经整理好的正文，保留原有数字与限定条件。

[原文](https://example.com/article)

## 工具与项目

### 项目名称

粘贴你已经整理好的项目介绍。

## 一周动态

粘贴本期动态原文。
```

章节颜色按名称匹配：

| 颜色 | 栏目 |
| --- | --- |
| 赭红 | 今日主线、主线、今日要点、本周导读、本周精选 |
| 靛蓝 | 人物精选、人物、好文章、文章、深度阅读 |
| 松绿 | 小工具、工具与项目、开源项目、项目、工具、好工具 |
| 赭金 | AI 资讯、一周动态、本周动态、动态、资讯 |

自定义栏目按顺序轮换四种颜色。栏目顺序、标题和正文以 Markdown 为准。

支持列表、引用、代码块、表格及链接。普通网址可自动成为链接，显示文字保持原样；原始 HTML 作为文本展示。图片放在本期工作目录下的 `images/` 中，使用 `![图片说明](images/文件名.png)` 引用。支持 PNG、JPEG、GIF、WebP，单图最多 10MB。远程图片先自行保存到本地。

### 预览、修订与发布

- 初始化保留已有文件。预览只读草稿，在同一私人工作目录生成 `preview.html` 和校验记录。
- 预览服务仅监听本机地址，提供本期预览与 `dist/` 的公开文件。本期定稿并构建后才会进入归档。
- 修改 Markdown、图片或模板后，重新运行预览并审阅；周报需要你重新确认更新后的预览。正在运行的预览服务按 Ctrl+C 停止；供你审阅的服务在审阅结束后再停止。
- 定稿检查草稿、图片、预览以及当前模板的一致性，输出与审阅过的 HTML 完全一致。
- 修订已存在的同一期时，确认后添加 `--replace`：例如 `npm run daily:finalize -- 2026-11-05 --replace`。旧式 `YYYYMMDD.html` 日报也受同日保护。
- 只生成预览文件、不启动服务：`npm run daily:preview -- 2026-11-05 --no-serve`；周报同样支持。
- 定稿和构建不会提交或推送。推送 `main` / `master` 会触发 GitHub Pages 发布。
- `report-publish` 按本次授权及当前分支情况提交、推送或走 PR，仅包含本次正式文件和必要资源，不混入无关修改。三个索引由构建生成，不手改；构建后检查三个索引、历史资源及私人素材隔离。
- 发布后核对对应提交的 GitHub Actions 与线上入口；仅创建 PR、推送功能分支或尚未验证部署时，应明确报告当前状态，不能声称已经上线。

素材、草稿、预览在 Git 忽略的 `.local/`，需自行备份；不提交到 Git，也不进入 `dist/`。Skill 的定义文件同样不会进入发布包。

### 可选的旧周报整理命令

如果你把原文放在 `materials.md`，可以明确调用 `npm run weekly:draft -- 2026-11-08`：合并同名栏目，删除完全重复条目，保留同链接但正文不同的内容。它生成 `draft.md` 与整理记录，不改写、概括或补写正文。该命令会去重，仅在你明确要求调用它或授权去重时使用，普通分类、重排和拟标题由 Agent 编辑草稿完成。人工编辑过的草稿受覆盖保护；重新整理需获得覆盖授权，先保存旧稿备份，再使用 `--replace`。

已有完整 `draft.md` 时，直接进入预览即可。

## 模板与验证

- `lib/publication.js`：共用 Markdown 渲染、预览和定稿。
- `lib/publication-page.js`、`lib/publication.css`、`lib/publication-reader.js`：正式 A 模板、章节配色、阅读与归档交互。
- `lib/daily.js`、`lib/weekly.js`：日报／周报的日期与工作目录入口。
- `lib/indexes.js`：报告、日报、周报索引；`lib/site.js`：公开文件打包。

样式规范见 [DESIGN.md](DESIGN.md)。修改正式样式后运行 `npm test` 与 `npm run build`，检查三个索引和阅读页。历史日报、周报保留原有 HTML，新生成的内容使用固定模板；设计提案和 `.local/` 均不进入 `dist/`。
