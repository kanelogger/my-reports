主题：把斯坦福 CS329Z 公开课拆成能看的讲座和能手写的作业 原链接

主题：把 Gemini Decisions API 的定价、限制和对照写清楚 原链接

主题：软件从给人用，变成给 Agent 用、让人更好验收 原链接

他把 Claude Artifacts 理解成软件使用主体从人变成 Agent，人负责审查和微调，并在后续帖里落到三处设计：能看见 Agent 正在做的操作和历史、用框选加自然语言代替复杂 GUI、先用选择题把模糊想法问清楚再出方案。功能发布本身昨天已经写过，今天新的是这个类比，以及验收而不是「会不会做」才是设计重心。展开见 原链接

我的看法：CS329Z 真正有用的是作业一禁止用框架，逼你把 harness 写出来，这比再看一门口头讲 Agent 的课值。Decisions API 那篇把免费层会拿数据、跑分来自 Google 自己都写上了，这比只转定价有用。软件改给 Agent 用的说法可以当观察，三个验收例子比 Docs 类比更落地，但还不能证明这就是下一轮软件的统一形态。

Cos(余弦) @evilcos

主题：提醒先不要更新 Telegram，消息里的应用缺少沙盒 原链接

新版 Telegram 支持在消息里带「应用」，但他说没有真正的沙盒保护，用的是 QuickJS，可能成为恶意代码的执行入口，并建议先观望、暂不更新。被引分析称所谓沙盒只是进程内解释器，缺少进程隔离。这里只保留风险结论，不转写利用细节。

主题：Ledger Clear Signing 会把签名上下文送到服务器 原链接

他指出该机制默认会采集签名时的网络或链 ID、目标地址、设备型号、固件和应用版本、是否盲签及原因等，位置不在固件里，而在 Ledger SDK 的 context-module v1.16 及以上。Ledger Donjon 的解释是：ERC-7730 描述符太大，默认要向 Ledger 服务器解析，官方称不存储这些数据。会发送哪些字段，和官方说不存储，是两件不同的事。

我的看法：Telegram 这条该听，花哨功能如果跑在客户端同权解释器里，风险大于便利，先不更新是合理建议。Ledger 的关键不是「官方承认存了数据」，而是这些字段默认就会离开设备；不存储只能说明留存政策，不能等同于未采集、未发送。
