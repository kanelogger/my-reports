人物

Sac @Saccc_c

主题：AnliBili，把十六年社媒安利压成 B 站精品库 https://x.com/Saccc_c/status/2117620059392942489

受 Karpathy HackerTube 启发，他做了 AnliBili，专门收「被反复安利」的 B 站视频。材料来自知乎、小红书约十六年近一千万条讨论，筛出 1132 个片子，每个至少被三个人、在三个不同月份推荐过。

筛选不是手工扫完，而是用 Teamily AI 的 team agents 搭 Loop：整理评论 → 筛选视频 → 分类上线，循环扩充。人和 Agent 待在同一个群里共享上下文，他说一句「加小红书数据源」，团队就会重新分工再跑一轮。

站点在 https://anlibili-site-bxlxh4ai.teamily.run ，后面还要继续加片。

我的看法：推荐热榜越吵，越有人愿意用「多人跨月」这种硬门槛自建信息源，这比又一个聚合 App 更值得盯。

Orange AI @oran_ge

主题：关思考涨六倍，给权重编程降温 https://x.com/oran_ge/status/2117626509095837948

有人发现只要关掉 Qwen 的思考模式，数学表现就能抬大约六倍，根本不用动权重。他把这条甩出来，直接冲着前夜刷屏的「权重空间编程」叙事。

同一时段他也跟了 Cat Wu 离职：Claude Code 核心又走一个，并吐槽 Anthropic 的上市信仰绑定有点反人性 https://x.com/oran_ge/status/2117767285775696372

我的看法：基线实验一松，六倍数字会瞬间掉价；人事吐槽可以当情绪样本，别当成离职原因已经查清。

宝玉 @dotey

主题：Cat Wu 离职、/retro 实证、简历课与 Design Harness https://x.com/dotey/status/2117739064455463086

Claude Code 与 Cowork 产品负责人 Cat Wu 发文说周五是在 Anthropic 最后一天，没写原因也没写下一步。她早年做过 Scale AI、Dagster 工程师，经 Index Ventures，2024 年 8 月进 A 社。

另一条长文盯 /retro 一类「干完活让 AI 改自己的 Skill」做法，并拉出论文《How Do Coding-Agent Harnesses Self-Evolve?》。作者在 SWE-bench 上跑 Claude Code，有效测试里只有两项改动真正消掉目标问题，有的改动还会在无关任务上加多余检查 https://x.com/dotey/status/2117706197797114009

他还翻译了 OpenAI 应用 AI 工程负责人 Wulfie Bain 的简历四条：写短、删无关、写成果、方便扫读 https://x.com/dotey/status/2117639131929129316 ；并更新 Baoyu Design Skill 的 DeepSeek Harness 插件，统一入口看 Slides／Design／Dashboard／Motion https://x.com/dotey/status/2117838908721660026

我的看法：/retro 这篇比「自我进化」口号值钱，它把「改手册就能变强」压回可测结果；Cat Wu 则提醒你，产品走红不等于团队稳态。

歸藏(guizang.ai) @op7418

主题：Siri 的 App Intents，超级应用要重新表态 https://x.com/op7418/status/2117804545829171299

苹果更新 App Intents，开发者可以把自家 App 功能开放给 Siri AI，改上车点、挑收藏商品、跨 App 把商品丢给聊天软件里的朋友。还内置一套偏 Agent Skill 的子集：先读 Skill，再判断请求是否匹配。

他提醒：以前豆包想自动操作国内超级应用，多半被拒；现在 Siri 也有类似能力，后续各家怎么开权限会很好看。开发者可从 27.3 测试版开始接。

同一波他也跟了 Cat Wu：有人问是不是 IPO 前离职股票无锁定期，她说这不是她考虑的因素 https://x.com/op7418/status/2117793035597795755

我的看法：系统级入口一旦能调第三方，超级应用的「拒绝代操作」策略就得重写，这比又一个提示词库更像规则变化。

yetone @yetone

主题：Alma Personal Agent 上线 https://x.com/yetone/status/2117707111790752185

继前面的安卓与远程控制能力后，他宣布 Alma Personal Agent 正式上线，并配了演示视频。

我的看法：Personal Agent 赛道拼的是真能替你动手，不是聊天壳再换皮；上线只是起点，后面要看失败率和权限边界。

郭宇 guoyu.eth @turingou

主题：Personal Agent 管买房，Agent 管扩容 https://x.com/turingou/status/2117789717848834157

他继续感叹用 Grok bot 管土地规划和买卖房子，认为长久信息偏好加自我改善循环，会推高人对 AI 的信任，Personal Agent 会挤掉不少传统中介式岗位。

另一条更硬：如果 Agent 能盯服务器负载、自动开裸金属并调度资源，为什么还要绑死大型云和它们的糊涂账单 https://x.com/turingou/status/2117792028734136678 。傍晚他写完全自动运维，VPS 开机到可用中位数约 94 秒，裸金属约 6 分钟；存算分离下，高峰每天用不满 8 小时，ROI 就可以是正的 https://x.com/turingou/status/2117960780566184373

Tuwa 侧，他说昨天一口气发了三十多个公开测试版，年初还做不到这种自动化密度 https://x.com/turingou/status/2117783400916664779

我的看法：从代打电话走到按负载开机器，叙事已经离开「助理」进入「替代云控制面」；真要落地，账单透明和误操作熔断比演示速度更重要。

Tw93 @HiTw93

主题：妙言加 CLI，给 AI 时代留一个能手写的本地笔记 https://x.com/HiTw93/status/2117903730494591205

他说以后不靠 AI 写东西的人会越来越少，但自己在妙言里仍坚持手写。妙言是他多年打磨的原生 Swift Markdown 应用，强调规范语法、本地、高性能，不做破坏格式的所见即所得，还带类 git 的本地版本回滚。

今年补了 iPhone／iPad，并把重心放在移动端预览和阅读。为了对齐 AI 工作流，他加了 CLI：miao open、new、search、list、cat。站点 https://miaoyan.app

我的看法：在人人用 AI 生成 md 的时候，坚持「给人读的成品编辑器」反而是差异化；CLI 比硬塞聊天框更对工程师胃口。

Cos(余弦) @evilcos

主题：币安被盗别只看戏，对照自己的投毒面 https://x.com/evilcos/status/2117768409144594727

很多人看完币安披露，觉得工程师 A／B／C 弱、权限离谱。他提醒这是 APT 过程：人性利用、情报踩点、免杀、信任链、横向投毒、云渗透、风控绕过、0day 穿插，看戏最轻松，自己中招才知道层次。

他要人去查：自己会不会被投毒，同事会不会，公司员工会不会，别停在吃瓜。

我的看法：事后诸葛便宜，把披露当检查清单才值钱；「低级错误」四个字常常只是你没站在攻击链上。

Barret李靖 @Barret_China

主题：企业内部的「上翻」 https://x.com/Barret_China/status/2117798934718665118

他把基建和应用能力改造成 MCP、CLI、Skills 这件事概括成「上翻」，类似控制反转，把编排权交给上层 Agent。Claude Code 爆火大半年后，很多公司内部已经变得更 AI Friendly。

C 端 Personal Agent 也是同一逻辑：应用把自己拆成插件或原子能力，喂给 ChatGPT、Grok 或 MCP。他判断 2026 年底关注点会从「AI 能做事」转到「能交付结果并为此付费」。

我的看法：上翻说清楚了企业 Agent 的瓶颈不在模型口号，而在内部能力有没有被暴露成可编排接口。

Jiayuan (JY) Zhang @jiayuan_jy

主题：用 Multica 开发 Multica，再加对抗式 review https://x.com/jiayuan_jy/status/2117868868844880270

他晒了团队如何用 Multica 开发 Multica 本身，把自举流程摊开。

另一条给出对抗式 code review prompt：每次当独立审查者、安全要审但别航天级、要改就 mention Lambda 改完再审、吵不完再拉人决策，并绑成 Quick Action 小循环 https://x.com/jiayuan_jy/status/2117861662963511307

我的看法：自举故事好懂，真正可抄的是那套「可收敛的 review 环」，比再发一张架构图有用。

圖拉鼎 @tualatrix

主题：App Store 还在变密，AI 回复一眼假 https://x.com/tualatrix/status/2117858782827163739

他回看一年前的判断：越来越多人开通 Apple 开发者账号，越来越多 App 上架，趋势没减弱，App Store 短期内还会繁荣。

另一条点破 AI 回复模板：先复述你的原文，再给观点，最后甩问题；建议下次直接提问，省 Token 也不那么好认 https://x.com/tualatrix/status/2117619449822101725

他还准备打开千问，体验国行 Apple 智能 https://x.com/tualatrix/status/2117837623742058945

我的看法：商店侧仍在扩表，模型侧却越来越像填空题；模板被拆穿后，再装深度只会更尴尬。

李继刚 @lijigang

主题：重读 March 的探索／利用 https://x.com/lijigang/status/2117823012468646029

他读 1991 年 March 的《Exploration and Exploitation in Organizational Learning》，把组织资源分配拆成 Exploitation（改进已有）和 Exploration（尝试新东西），并提到文中的互相学习模型。

我的看法：Agent 团队天天加 Skill、加模型，本质上还是 EE 分配问题；这篇旧文刚好给「只卷工具不留探索预算」敲一下。
