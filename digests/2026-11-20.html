人物

宝玉 @dotey

他把 Dario 的上市致辞译了出来： 这是 Anthropic 官方账号发出的致辞，宝玉做了中文翻译。Dario 说创立公司是因为最强大的技术应当为全人类的福祉而打造，并提到他和妹妹 Daniela 曾因病失去父亲，那种病在父亲去世几年后变得可以治愈。他从生物学起步，后来说真正走进实验室才看到新药研发有多难。完整表述以 Anthropic 原帖为准。原链接

Claude Code 团队怎样审代码： 他根据 Claude Code 产品经理 Morgan Lunt 的分享整理。大约九个月前，模型已经可以独立做完一个功能，PR 堆积，审查成了最慢的环节。Lunt 把早先那种互相盖章、只扫一眼的审查叫作「歌舞伎表演」。后来改由智能体做大部分审查，人只在高风险改动上签字，目标是 90% 的 PR 合并时，除了让 Claude 干活的那个人，不再找第二个人。Lunt 给出的结果是：查出实质问题的 PR 比例从 16% 升到 54%，合并的 PR 数量翻了一倍，需要回滚的 PR 少了 40%。他们用自家历史上的线上事故做成评测集，不用人为埋 bug 的合成数据。这些数字来自 Lunt 的分享和宝玉的转述，原文在 Anthropic 的这篇博客。原链接 原链接

他说程序员不死，只是凋零： 他认为传统意义上的程序员其实早就在变，从机器语言、汇编到自然语言和 AI 协同，核心仍是把模糊的人类意图转成精确的逻辑规则。变的是人与机器之间的那层翻译工作。这是他的判断，不是调查数据。原链接

我的看法： 致辞适合对照官方原话来读，情感故事解释不了发行价和收盘价。代码审查那组数字更值得看，因为它把「查得出问题」和「回滚有没有变多」放在一起，也坦白过机器人互相打架、一个 PR 改出上百次提交的阶段。16% 升到 54% 是他们自己的评测口径，换一套事故样本未必是同一个幅度，但「先有考题再撤人工」这个顺序是对的。

Android Studio 里真的做了元素周期表选型器： 他没想到谷歌会把 Hydrogen、Neon、Carbon 这种命名直接做成周期表界面，并觉得对英语用户也不直观，看不出哪个元素是大模型、哪个是小模型。这是界面观察。原链接

他记下了 Anthropic 敲钟： 并转发了现场画面。首日交易的价格和估值见后文 AI 资讯，以交易所和可靠报道为准。原链接

我的看法： 动效和设计还原如果真明显好于 Opus，那是 Neon 最该被认真对待的地方，但它替代不了榜单和价格已经写过的定位。周期表选型如果要用户先记元素，就是把内部命名暴露成了使用成本。敲钟帖是记录，不是分析。

郭宇 guoyu.eth @turingou

他把开发工作往 Claude Code 和 Codex 的云环境里迁： 他集中看了这两家自带的云主机，觉得比预想的强大。机器是临时的，但按订阅账户来算，不用就浪费了。他已经把东京开发服务器上的一部分流程改成云电脑兼容配置，打算以后让东京的机器只做构建和部署，把开发从本地拿开，再把 Mac mini 和 Mac Studio 改成 CI。他的判断是，个人计算设备会越来越像显示和交付终端。原链接

他补充了云环境怎么用： 当天额度又用完了，但他大部分时间是在手机上操作云端项目。他说把推理和计算放在一处，约八到九成自动化工作可以不弹权限卡片就做完，云环境也可以复制到其他 Claude Code 账号。他还写到，云环境重建后可以用初始脚本把 Chrome 登录态拉回来，并把 Cloudflare 或公司 Stripe 的可读密钥放进云环境密钥库。这是他的做法，不是官方推荐，密钥放进临时共享机器本身就有泄露面。原链接

他很推崇 Nuance Labs 的数字人： 称这是他用过最自然、反应也非常快的数字人。这是演示观感。原链接

我的看法： 把订阅附带的云主机用起来，这个方向说得通，本地机器改去跑 CI 也符合他描述的工作流。可他把登录态和可读密钥放进会重建的共享云环境，这个风险比省下的那几百毫秒延迟更值得先想清楚。数字人好不好看，还需要更多并排对比，单凭一条演示不够。

meow @meow2149

他转述了 Google 开源审查 Agent Sashiko 的内核数据： 团队跟踪了 2.15 万个主线提交。审查未发现问题的补丁，合并后 60 天内有 0.9% 需要补修；收到严重警告但仍合并的补丁，这个比例是 7.6%。这是对已合并补丁的观察统计。官方博客写于 11 月 18 日，数字可以对上，并补充：Sashiko 由 Google AI 与基础设施团队用 Gemini 构建，已捐给 Linux 基金会；启用后，Linux 7.2 的 60 天补修率从历史基线 3.4% 降到 2.2%。原链接 原链接

Orca 的 GitHub 仓库突然 404： 他一开始以为项目删库或停更，后来发现是整个 GitHub Organization 被标记并隐藏。官方表示还没收到明确限制原因，也没发现异常活动，猜测可能和当天转移了一个 GitHub App 有关。他说这是一个标了 12.9 万星以上的开源项目，希望 GitHub 尽快审核恢复。组织是否恢复，这条帖子不能当作最终状态。原链接

Onlook 2.0 把本地网页放进设计画布： 点中要改的元素，就可以让 Claude Code 或 Codex 按选中内容改源码。每个设计项目有自己的 Git worktree 和分支，改完的代码可以开成普通 GitHub PR。它是开源桌面应用，支持 Apple 芯片和 Intel 的 Mac。原链接

我的看法： Sashiko 这组对比有用，因为它比较的是合并后再修的比例，不是「报了多少条」。干净通过只有 0.9%、带严重警告却仍合并则是 7.6%，说明警告不是纯噪音，但选择合并的人已经承担了更高返工率。Orca 被整个组织隐藏，对用户是真实中断，在 GitHub 说明原因之前，不宜写成项目停更。Onlook 如果真能从画布改回源码并开出可审查的 PR，比再做一个只出图的设计套壳更值得试。

阑夕 @foxshuo

他把腾讯和字节的办公 Agent 口径放在一起看： 腾讯三季报确认 WorkBuddy 日活刚过 1000 万、每天消耗 Token 达到 100 万亿，并称它是中国用量最高的 AI 应用。这些是昨日已核对过的官方表述。阑夕补充说，豆包有 2 亿日活，用户规模约是 WorkBuddy 的 20 倍，用量却被超过，他觉得意外。他转述字节晚上的回应：豆包工作日活过了 800 万，企业客户 ARR 超过 20 亿人民币。他还写到，腾讯电话会议用「最近 7 天年化收入」的口径，把 7 天收入乘以 52，折算超过 5 亿美元，也就是预计年入约 33 亿人民币。豆包工作的日活和 ARR、以及 7 天年化这个口径，是他的转述，我没有单独拿到字节或腾讯电话会的原始文本。原链接

他整理了马斯克在 DealBook 峰会连线里的一批判断： 包括把请走黄仁勋比成赛季中把乔丹踢出公牛队、说没人能真正取代黄仁勋、并称如果 Anthropic 真的在做坏事会终止算力合同，但觉得还不会到那一天，对方还在找他要 10 吉瓦以上的算力。这是马斯克的个人说法，不是董事会或合同文本。原链接

我的看法： 7 天收入乘 52 这个算法，用来在电话会上压过对手很方便，却很难当作可对比的年度收入。字节回以 800 万日活和 20 亿 ARR，比继续比 Token 更像在改裁判规则。两边的日活都还没有拆开「有多少是为了领积分或被入口导流」，先不要把用量第一写成产品第一。马斯克那些类比可以当压力信号，改变不了已经发生的人事结果。

葬AI @Entertheriver

他不认办公 Agent 的 DAU 宣传： 他说豆包工作 800 万日活，本质是飞书和豆包 App 导流；WorkBuddy 的 1000 万日活，则和线下铺设有关。他还点了百度搭子月活逼近 1000 万、库库 AI 用户突破 5000 万、商汤小浣熊月活超过 900 万，认为传统 App 往里塞用户的成分很大。收入口径他觉得更有价值，但腾讯把最近七天收入年化成超过 5 亿美元、并称是腾讯会议的两倍以上，让他想起某些模型公司的算法。按他的换算，最好的 7 天收入是 6500 万人民币，最好的一天不到 1000 万，折合下来人均贡献不到 1 块钱。这些换算基于他转述的电话会口径，不是我独立核算的财报数字。原链接

腾讯三季度资本开支： 他写资本开支是 814 亿元，同比增长 5 倍，并希望游戏业务能撑住混元团队的开支。这个数字应以腾讯已发布的三季报为准，此处先记作他的转述。原链接

我的看法： 他把 DAU 从「看起来很大」拉回获客路径和人均贡献，这比继续转发 1000 万有用。可人均不到 1 块钱，用的是最好 7 天再除以 1000 万日活，日活里有多少是有效付费用户并没有拆开，只能说明 C 端现在很难看，不能直接推出办公 Agent 只能做 To B。资本开支翻倍是真风险，不过要把 814 亿和混元一一对应，还得看财报里的分项，不能只听这句感慨。

Orange AI @oran_ge

他把上市日写成谷歌在开枪、OpenAI 只掏出弹弓： 本以为 OpenAI 要狙击 Anthropic 上市，结果觉得 Sam 只是掏出了弹弓，谷歌则一个接一个地发，还说明天还要发。这是情绪判断，不是发布日历。原链接

他解释谷歌为什么突然变强： 转述说 Gemini 的强化学习团队把一篇批评 DeepMind 的文章打印出来贴在桌上。那篇文章的核心判断是：DeepMind 已不再是前沿实验室，原因是强化学习团队大量离职和算力分配不佳，再次达到 SOTA 的可能性已下降为零。Orange 的结论是，根本原因还是团队给整好了，公司并不缺数据和卡。批评文章是他转引的卖方或客户观点，不是谷歌的官方检讨，也没有在这条帖子里给出可核对的离职名单。原链接

我的看法： 把最近的模型发布理解成「团队被刺激之后重新打好了」，逻辑完整，但那篇「达到 SOTA 的可能性已下降为零」写得太满，事实已经打脸，说明当时的算力分配和人员流动判断即使有依据，也不能外推成实验室已经完了。上市日谁在「开枪」更像叙事，对收盘价没有解释力。

Barret李靖 @Barret_China

他认为中间文档会变少，知识入库会变成旁支： 以前开完会要整理 PRD，再更新技术方案，最后才写代码。现在很多决策在会议和群聊里就已经产生，并可以直接指导代码。他们团队有些需求是讨论完就进入开发，由 AI 结合历史资料和沟通上下文实现，文档按协作需要再补。他的重点是：大量只给 AI 消费的中间文档可能会越来越少，人要读和要协作的内容反而应该更精简，质量要靠验收标准、自动化测试和工程约束来兜。原链接

我的看法： 这比「以后不用写文档」清醒，因为它把省掉的是给 AI 看的中间层，不是给人看的验收和约束。风险也清楚：如果群聊上下文并没有被可靠保存，或者验收只覆盖了高兴路径，省掉 PRD 之后出问题会更难回溯。先把测试和约束补上，再减文档，这个顺序不能反。

Kasong @kasong2048

他解释为什么大规模程序员裁员还没来： 三条理由。当前模型并不是按「代码长期演进轨迹」做强化学习，局部合理但长期腐化的设计不会被惩罚；因此普通模型长时间无人看管会快速积累偏差，SOTA 模型要修复这些偏差又会消耗大量 token；而 token 成本仍高于雇程序员来维护架构的成本。原链接

我的看法： 这比「AI 还不够强所以没裁员」更具体，因为它把问题和训练目标对上了：短期能把测试跑绿，并不等于长期架构不会烂。可「token 比雇人更贵」会随价格和模型能力一起变，这是此刻的成本结构，不是一条可以外推一年的定律。真要验证，得看无人值守跑几周之后的返工量，而不是只看单次生成能不能交差。

idoubi @idoubicc

他用了半个月 T3 Code，又换回 Termany： 把工作环境从 Mac Pro 迁到家里的 Mac mini 后，他需要跨设备操控 Agent。T3 让他喜欢的是手机也能继续管家里的任务、同一对话里能切换 Claude Code 和 Codex，以及 GUI 更舒服。不喜欢的是：项目按文件夹组织，每个项目只能挂一层 session，并行一多就不好切；GUI 通过 ACP 调度 Agent，再加上跨设备延时，经常连接中断；任务状态也不够清楚。Termany 是 TUI，直接跑 Agent 的原生 CLI，多层文件树可以同时铺开更多会话，响应更快。它之前没有跨设备能力，他为此写了组网服务，并称已支持内网互联和端到端加密，云端互联版本也可以用同一个账号从外出设备接入家里的 Mac mini。Termany 还没有手机 App，也不能在不同 Agent 之间同步上下文，这两项他说还在做。原链接 原链接 原链接

我的看法： 这是少见的、用了半个月之后还愿意把短处写清楚的对比，比「又一个套壳更好用」有参考价值。跨设备如果真经常断连，对挂着跑的 Agent 就是硬伤。组网和端到端加密是否达到他写的程度，需要看实现和默认配置，不能只根据介绍认定外出接入已经足够安全。

花果山大圣 @shengxj1

他用谷歌新模型把北交大做成了能在浏览器里逛的 3D 校园： 7 分钟实测视频里，先尝试截百度地图全景再做图生 3D，教学楼发灰发绿，后来改让模型写脚本调 Blender 建模，并用 CLAUDE.md 里定好的双模型分工：主模型负责规划、架构和验收，编码模型专门写代码。视频里可以换角色、逛明湖、进天佑会堂、去体育场踢球。他用 Pro 和 Ultra 两个账号轮着跑，对成片满意，也说 Antigravity 的缓存确实不行。这是个人演示，不是可复现的评测。原链接

我的看法： 先规划再写脚本去建模，比直接图生 3D 更像能落地的工作流，校园能逛起来也说明这条链路已经能交出东西。可「缓存不行」被他一笔带过，如果这是 Antigravity 在长任务里的常见毛病，它会直接限制这种项目能不能稳定做完，不能只看成片的前半段。

CuiMao @CuiMao

他拒绝给 Anthropic 上市鼓掌： 他说如果几十年后真发生 Dario 所说的智械危机，废土里的幸存者翻出 2026 年 11 月 19 日的报纸，头版会是一家前九个月净亏上千亿美元的公司，靠制造「可能取代人类」的模型，做成人类史上最值钱的 IPO。稍后又写，对这只股票完全没有兴趣，认为涨幅里必定有被封号却没有退款的钱，脏。前九个月亏损「上千亿美元」是他的表述，我没有在这条讨论里核对最新财报数字。原链接 原链接
