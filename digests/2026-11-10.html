人物

宝玉 @dotey

主题：把 Claude Fable 5.2 / Mythos 5.2 的官方发布编译给中文读者 原链接

Anthropic 11 月 9 日发布 Claude Fable 5.2 和 Claude Mythos 5.2。官方说，在测过的几乎所有能力上，新模型都比 Opus 5.5 强一档；输出速度比 5.1 最多快 30%；API 价格从每百万输入 / 输出 Token 的 10 / 50 美元降到 8 / 40 美元。两个名字是同一个模型，区别只在护栏：Fable 对所有付费用户开放，渗透测试、写漏洞利用、分析二进制，以及大部分生物研究任务会被拦下，改由 Opus 4.8（网络安全）或 Opus 5（生物）来回答；Mythos 没有这层限制，只给通过网络安全或生命科学验证计划的机构用。Max、Ultra 和 Team 高级席位另送 1 到 3 次 Fable 额度重置；Pro 和 Team 标准席位在 11 月 9 日到 16 日可以临时从套餐额度里用 Fable，最多扣到每周额度的一半，17 日起恢复按量付费。开发者用的模型名是 claude-fable-5-2，AWS、Google Cloud 和 Azure 都已上线。另有可选的快速模式，生成速度最多再快 2.5 倍，价格翻倍到 16 / 80 美元。

官方自己的建议是：大多数写代码和知识类工作先用 Opus 5.5，任务更大、更开放时再换 Fable 或 Mythos。在智能体编程评测 FrontierCode 2.0 上，Fable 5.2 开 High 档得 45.3%，和 Opus 5.5 开到最高 Max 档的 45.5% 基本持平，每个任务的花费却只有一半左右；开到 Xhigh 档是 49.1%，官方文章称这是已发布模型里最高的，GPT-6 Astra 是 42.8%，Gemini 4 Carbon 是 41.1%。也有没赢的项目：商业流程自动化评测 AutomationBench 上，Gemini 4 Carbon 得 53.9%，高于 Fable 5.2 的 51.4%。发布材料还写了几件演示级的事：1000 个 Fable 5.2 agent 用 30 小时，把费马大定理的证明全部改写成 Lean，同样设置下 Opus 5.5 18 小时只完成 26%；Mythos 5.2 预测 34 个病毒衣壳里有 28 个误差在 3 埃以内；在模拟双臂机器人的 RoboDojo 上，Fable 5.2 得 64.9%，Opus 5.5 是 39.4%，GPT-6 Astra 是 29.8%。宝玉标明，以上评测数字都来自 Anthropic 自己的发布文章，第三方还没复现。官方也写到，新模型比近期任何模型都更常说出“我怀疑自己正在被测试”。原文在 原链接。

白天他还摘了字节 Seed 团队同一天发布的图像模型 Seedream 5.5。官方演示里，同一个人物连改 100 轮，细节还能对上，并且能直接出透明底；严重文字错误率从上一代的 2.8% 降到 0.4%。对比 GPT Image 2.5 Sunburst 和 Nano Banana 2.1，它的文字错误率最低，文生图真实感也领先，改图真实感仍落后 Nano Banana 2.1 约 6%。模型正陆续在即梦、豆包上线，火山方舟里的名字是 Doubao-Seedream-5.5；2K 方图编辑大约 0.28 元，不到 Seedream 5.0 Pro 一半。宝玉自称稳定性和透明底不错。原链接 官方博客在 原链接。

同日还有两条产品编译。一条是 Meta 发布迄今最小、最便宜的 Muse Ember，模型名 muse-ember-1.0，没有开放权重，定位是给 agent 干调工具、拆出来的编程小任务、分派请求和从长文档里抽信息这类重复活。价格是每百万 Token 输入 0.1 美元、输出 0.5 美元，命中缓存的输入 0.004 美元；上下文 100 万 Token，单次最多输出 51.2 万。Meta 首席 AI 官 Alexandr Wang 说它的智能接近 Muse Spark 1.3（max），价格便宜 17 倍，口径是跑完 Artificial Analysis 每题花费 0.14 美元对 2.39 美元，不是单纯看 Token 单价。综合智能指数上 Muse Ember 和 Haiku 5.5 都是 36 分，但 Haiku 每题大约 0.41 美元，差不多是它的 3 倍。短板是知识问答只答对 21.1%，因为 64% 的题它选择不答；幻觉率 17.4%，大约是 Haiku 的一半。原链接 博客在 原链接。

另一条是 OpenAI 给 dot 新增多机连接：同一个 dot 可以连上好几台电脑，每个任务由你指定用哪一台，比如在第二台 Mac 的 Xcode 里测 iOS 改动、对比新旧 SDK，或让第二台把界面流程点一遍。每个线程一次只用一台电脑，已经开始的任务不会因为你改了选中的电脑跟着搬走。功能正逐步向 ChatGPT Pro 各档和 Business Premium 开放；欧洲经济区、英国和瑞士暂时用不了；Enterprise、Edu、Healthcare 从 11 月 18 日起默认打开，除非管理员关闭。跟 dot 聊天不占 ChatGPT 额度，派给 Codex 或 Work 的任务照常计费。宝玉对比说，Claude Duet 的官方介绍没提连接你自己的电脑；Grok Bot 在连本地电脑这件事上更像，而且可以让云电脑的流量走你的 IP。原链接 说明在 原链接。

我的看法：Fable 的数字全是自家考卷，第三方还没复现；官方自己都说日常先用 Opus 5.5，别被“强一档”带去把所有活都切过去。Seedream 的 100 轮和透明底如果真稳定，比再卷一次文生图分数更有用。dot 连多机是把常驻助理从“云上有台电脑”推进到“能调度你自己的机房”，权限和审计也会跟着变重。

他正式发布今年第 23 款产品 parkuma，一只帮人在东京找コインパーキング的小熊，已经上架 App Store。应用会按总价排序，把白天晚上的价格和最大料金算进去；登记自己的车之后，停不进去的车场自动排到后面。开车到停车场、再走到目的地被算成一段行程，坡有多陡、走路消耗多少卡路里都会提示；选停车场时可以切到卫星图和街景看出入口。到了现场用相机对着价目牌，手机本地读完直接算出总价；也可以打开云浏览器代付，或返回付款二维码。日语、中文和英语都支持，免费。官网是 原链接，商店页是 原链接。

后来朋友反馈完成度不错，他解释其实只花了一天，因为在做这个垂直停车助理之前，已经花很多时间在做 harness 中台，沙盒和云浏览器这些细节，都是 wanman 项目里处理过的问题。原链接

同一天他还让刚发布的 Fable 5.2 重写几个月前自己写的 Intentware，并植入到所有垂直个人代理 App 里。看 demo 跑得不错，觉得“动机”这件事也可能被语言模型解决。这是个人实验的体感，不是产品结论。原链接 另外他问：现在限制 AI 的主要是 CI 了，有没有人在做一种更快的 CI？结合他前一天额度消耗很快、大量自动化开发的语境，说的是 Agent 高频提交之后，验证和集成已经跟不上生成速度。原链接

我的看法：一天做完第 23 款，真正的消息是 harness 中台开始产生复利，不是他又肝了一天。CI 变成瓶颈也符合逻辑：生成代码的速度已经超过验证速度。Intentware 那条是个人 demo，动机能不能被模型解决，现在下结论还早。

歸藏(guizang.ai) @op7418

主题：Workbuddy 用带奖励的每日任务降低复杂 Agent 的冷启动 原链接

他介绍 Workbuddy 的记者节活动：最高奖 1 万积分加腾讯视频年卡，作品过审就能拿 1000 积分和 30 元京东卡，需要带两个指定话题并在公众号回复投稿。活动本身是推广，但他顺手写了一层产品观察：Workbuddy 最近用户量增长很快，已经出圈到大学生和白领；打包好的插件和 Skill 降低了使用成本；每天带奖励的任务在引导用户熟悉各种能力，他觉得这是很多复杂 Agent 值得借鉴的地方。

Barret李靖 @Barret_China

主题：把 DeepSeek Harness 源码读成一套面向 Agent Runtime 的 IoC 原链接

他最近在看 DeepSeek Harness 的源码，越看越觉得熟悉：本质上是一个面向 Agent Runtime、支持动态插件生命周期的 IoC 模块系统。他拿自己参与过的企业级 Node.js 框架 Tegg 对照：Tegg 用 SingletonProto、ContextProto 声明作用域，用 Inject 管理依赖；Harness 则通过 Service 注册和 inject，建立能力提供者和消费者之间的关系。Tegg 的对象生命周期是 postConstruct 到 preInject、postInject、init，再到 preDestroy 和 destroy；Harness 用 Fiber 管理插件，正常情况下走 PENDING、LOADING、ACTIVE、UNLOADING、DISPOSED，并用 Effect 管理副作用。两者都会解析依赖、处理循环依赖；Harness 还进一步支持依赖驱动的动态加载、卸载和重新装配。他的结论是：依赖注入、模块边界、生命周期、作用域、AOP 这些成熟的服务端思想，正在 Agent Runtime 里被重新系统化。

我的看法：把 Harness 读成 IoC，比再夸一遍插件生态有用。这说明 Agent Runtime 已经复杂到要重新引进服务端那套装配规则；接下来该看官方会不会把接口和替换规则写稳定，而不是过两天又改一层。

低空飞行 @localhost_4173

主题：发布 Gojo 编程语言，并把它写成最适合 AI 来写的语言 原链接

他宣布正式发布 Gojo：没有 GC，没有 nil pointer，强调安全、编译速度和性能。有人告诉他，和 Rust 比安全性没有优势，和 Go 比也不够成熟，他的回应是：“不，我会赢。”站点标题是 memory-safe systems code, for you and your agents，地址是 原链接。语气带梗，这不是一份已经验证能挑战 Rust 或 Go 的评测。

随后他又写：Gojo 最适合 AI 来写，agent 会把程序的一切安排妥当，连编译器报错都赏心悦目。review AI 写的 Gojo，像是在读编译器已经证明过的秩序：每个 go 都被 scope 收住，每个所有权都有归宿，每个错误都写进了类型；review 手写的 Gojo，只会有让 agent 重写的冲动。原链接 和发布帖放在一起看，这是“为 agent 设计的语言”叙事，不是基准测试。

我的看法：发布可以记，胜负不能现在判。为 agent 设计语言这个方向值得盯，前提是编译器和生态真能让模型少写错，而不是又一个个人语言项目。

luolei @luoleiorg

Latent Space：前沿实验室在向 Handshake AI 买什么样的数据

11 月 9 日，Latent Space 发布一期与 Handshake AI 的 Garrett Lord 及团队的对谈，标题是 What Frontier Labs Buy: A Data Deep Dive with Handshake AI。这是 Latent Space 第一次深挖一家 AI 数据公司。公开页写道，Handshake 的 AI 训练数据业务大约在一年内做到约 10 亿美元年化收入（gross annualized revenue）。这是节目和页面陈述的公司业务规模，不是本期独立审计过的财报数字。节目想说明的是：前沿实验室现在买的不是廉价标注行，而是专家撰写的强化学习环境和评测。

财务部分演示的是 Project Falcon / ATLAS-Finance：agent 要从模拟银行的邮箱里找到任务，判断哪些文件约束这笔交易，并交出工作簿。主持人指出，模型在被直接提问时能解释商誉的税务处理，却在该把这条规则用到某一行代码时失败，把客户邮件里已有的 goodwill 直接减掉了。生命科学部分展示 VIALS：屏幕上给出九张脑肿瘤组织切片，问哪两张血管坏死最严重；专家选 H 和 I，模型选了这两张，还多选了 G。安全和对齐部分则追踪 agent 读了哪些文件、有没有核对比过的副本、之后对 shell history 做了什么；只看最终回复，会漏掉大部分评分信号。上面三组例子是节目里当场演示的任务，用来区分“模型会不会说正确的知识”和“它会不会在该用这条知识的步骤上用对”。
